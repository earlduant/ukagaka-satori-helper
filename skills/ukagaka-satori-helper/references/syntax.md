# 里々の記法

**辞書に触る前に通読する。**読むときも書くときも、ここに書いてあることが前提になる。

里々はエラーを出さない。知らずに書くと、動かして初めて分かるか、そのまま配布される。

## 評価モデル

**全角括弧が里々の唯一の評価単位。**内側から評価され、結果が構文として読み直される。

これが唯一の評価手段で、避ける選択肢はない。

```
（アイテム（C0））
    内側の（C0）が 3 に展開され、（アイテム3）という名前になる
    eval("アイテム" + eval("C0")) と同じ

（split（バイト値，１）（Ｒ０）（バイト値，１）-）
    （バイト値，１）が 0x01 に展開されてから、それが引数区切りとして読まれる
    引数の中身にカンマ類が含まれうるときに使う
```

引数の区切りは `,` `、` `，` `､` `0x01` の5つ。他言語の `,` に当たるものが5種類あると考える。
どれも初期状態で使えるので、上の例に追加の記述はいらない。

**逆に、引数の中にこれらが入ると、そこで切られる。**
展開した結果に紛れ込んでも同じで、書いた時点では見えない。
→ [引数区切りの誤爆](#引数区切りの誤爆)

擬似配列も、動的な呼び出しも、区切り文字の差し替えも、すべてここから導ける。

評価されるのは括弧だけ。辞書を評価している間、さくらスクリプトは1文字も機能していない。
`\![embed,…]` の `\!` も `[` も `]` も、里々にとってはただの文字である。

- 「タグの内側か外側か」という区別は存在しない。 `\q[…]` の中でも `（…）` は同じに展開される
- さくらスクリプトが意味を持つのは、里々が文字列を返した後

**エラーが出ない。**未定義は報告されず、型もなく、引数の数も検査されない。
例外は括弧の対応だけで、これは報告される代わりにそのファイルが丸ごと無効になる。

## 定義

行頭の全角 `＊` （文） `＠` （単語群）で定義が始まり、次の `＊` か `＠` が来るまでが1つの定義。
ファイルの先頭から最初の `＊`／`＠` までは無視される。

```
＊文	採用条件
本文
本文

＠単語群	採用条件
候補1
候補2
```

- `＊` は定義全体で1つのトーク。 `＠` は1行が1候補
- 名前を書かない `＊` はランダムトークの候補になる

行末に `φ` を置くと、次の行と繋がる。

```
＠単語
あφ
い
```

「あい」という1候補になる。2候補ではない。
長い候補を折り返して書くときに使う。

### 採用条件

名前の後ろに**タブ**で区切って書く。展開した結果が真なら候補になる。

```
＊定義名	（進行度） >= 3     条件つき。真のときだけ候補になる
＊定義名                        条件なし。必ず採用される
```

省略は `1` を書いたのと同じ。
偽の候補しか無ければ、そのイベントは 204（応答なし）になる。

真偽の判定は [条件式](#条件式) を見る。「空でなければ真」ではない。

| | `＊`（文） | `＠`（単語群） |
|---|---|---|
| 単位 | 定義全体で1つ | 1行が1候補 |
| 同名の定義 | どれか1つが選ばれる | 候補が合算される |
| 改行 | 自動的に `\n` になる | ならない |
| スコープ | `\0` / `\1` が自動挿入されうる（[下記](#先頭に挿入されるスコープとサーフェス)） | されない |

関数のつもりで `＊` を使うと、自動挿入された改行やスコープが戻り値に混ざって壊れる。

ウェイトはどちらにも入る。句読点からの自動挿入は、
括弧を展開し終えた最終的な出力に対して行われる。
`＠` から持ってきたセリフにも、`＊` に直接書いたのと同じように入る。

```
＊トーク
：こんにちは、今日はいい天気ですね。

＊トーク
：（あいさつ）

＠あいさつ
こんにちは、今日はいい天気ですね。
```

どちらも `こんにちは、\_w[36]今日はいい天気ですね。` になる。

`36` は固定値ではない。台詞の長さと設定で変わる。
入れたくないなら[ウェイトを止める](#ウェイトを止める)。

### 先頭に挿入されるスコープとサーフェス

**応答の先頭に `\1\s[…]` が自動で入る。**入るのは、そのイベントで
最初に選ばれた `＊` のときだけ。`＞` でジャンプした先や、
`（）` で呼んだ `＊` では入らない。先頭に1つあれば足りるため。

挿入される中身は `＄デフォルトサーフェス0` `＄デフォルトサーフェス1` の値。

トークの先頭でサーフェスを指定すると、`\0` 側は挿入されない。

```
：あ           → \1\s[10]\0あ
：（５）あ      → \1\s[10]\0\s[5]あ      デフォルトサーフェスは入らない
：\s[5]あ      → \1\s[10]\0\s[5]あ      さくらスクリプトで書いても同じ
```

トークが終わってしばらく後にも、同じものが挿入される。
辞書に何も書いていないのに表情が戻るのはこれ。

`＄会話時サーフェス戻し<TAB>無効` で、どちらも止まる。
辞書に書いたサーフェス指定だけが出るようになる。

挿入される値の決まり方、`＄サーフェス加算値` との関係、後から戻るしくみは
`internals.md` の「サーフェスの自動挿入」にある。

**`＠` に処理を並べて書くと、1行しか実行されない。**1つの括弧に収める。
字下げはタブで行う（[括弧の中の空白](#括弧の中の空白)）。

```
＠処理
（set,A,1）
（set,B,2）      ← どちらか1行だけが選ばれる

＠処理
（nop,
	（set,A,1）
	（set,B,2）
）                ← 両方実行される
```

### 単語群の中では行頭記号が効かない

`＠` を `（名前）` や `（call,…）` で呼ぶと、中に書いた記号は文字として出てくる。

| `＠` の中に書いたもの | 展開した結果 |
|---|---|
| `＄変数<TAB>値` | 代入されない。`＄変数<TAB>値` と表示される |
| `＞ジャンプ先` | ジャンプしない。`＞ジャンプ先` と表示される |
| `＿選択肢<TAB>行き先` | 選択肢にならない。`＿選択肢<TAB>行き先` と表示される |
| `：セリフ` | スコープが切り替わらない。`：セリフ` と表示される |
| `本文＃コメント` | **`＃` だけは効く。**`本文` になる |

どれもエラーにならない。記号を含んだ行が、そのまま画面に出る。

**`＠` の中で働くのは、括弧 `（…）` と `＃` だけ。**

| やりたいこと | `＠` の中での書き方 |
|---|---|
| 代入 | `（set,名前,値）` |
| 分岐 | `（when,条件,真,偽）` |
| セリフのスコープ | `\0` `\1` を直接書く |

`＊`（文）の中では行頭記号が効く。効かないのは、`＠` を括弧から呼んだときだけ。

### 同名の定義が複数あるとき

`＊` と `＠` で挙動が違う。

```
＊トーク
あ
い

＊トーク	採用条件
う
え
```

`＊` は定義のうち1つが選ばれる。
次の定義までの各行が `\n` で繋がれて返る。末尾に並んだ `\n` は除去される。
上なら `あ\nい` か `う\nえ`。行は候補ではない。

```
＠単語
あ
い

＠単語	採用条件
う
え
```

`＠` は候補が合算される。条件が真なら「あ・い・う・え」の4つから1つ選ばれる。
条件が偽なら「あ・い」の2つから選ばれる。

条件ごとに定義を分けて、候補を足していくのが常套手段。
どちらもランダムに選ばれる（重複回避の設定次第）。

### 1行とは、括弧が閉じるまで

括弧の中の改行は無視される。見た目の行数と、里々が数える行数は違う
（[括弧の中の空白](#括弧の中の空白)）。

```
＠単語群名
（when
,A == B
,1
,2
）
```

5行に見えるが、これで1候補。長い関数呼び出しを折り返して書ける。

## 行頭記号

**行頭にあるときだけ効く。**行の途中に書くと、ただの文字になる。

| 記号 | 意味 |
|---|---|
| `＄変数名<TAB>値` | 変数へ代入。右辺を計算しない |
| `＄変数名＝式` | 変数へ代入。右辺を計算する。半角 `=` も同じ |
| `＞ジャンプ先<TAB>条件` | 条件が真ならそのトークへジャンプ。条件を省くと無条件 |
| `＿選択肢名<TAB>ジャンプ先` | 選択肢を出す。ジャンプ先を省くと選択肢名と同じトークへ |
| `≫文字列` | あいまい検索。一致率が最も高いトークへジャンプする |
| `→` | 同時起動中の他ゴーストへ話しかける |

定義を始める `＊` `＠` も行頭専用（[定義](#定義)）。**この7つ以外に行頭専用の記号は無い。**

`≫` は `＞` と違い、完全一致では探さない。トーク名を `「　` で区切り、
後半を全角スペース区切りの単語として扱って、渡された文字列との一致率を点で計る。

```
＊試験「　ケーキ
：【マッチ】

≫試験「　ケーキ              ジャンプする
≫試験「　ケーキが食べたい     ジャンプする（単語が含まれている）
≫試験「　やきそば            ジャンプしない
```

一致率が基準に届かなければ、飛ばずに次の行へ進む。
候補を多く並べるほど点が下がって落ちることがある。
計算の仕方と、それを切り替える `＄コミュニケートの検索方法` は
`internals.md` の「一致率の計算」にある。

主にコミュニケート（`＊ユーザ「　○○`）で使う。

```
：か＄へんすう	5      代入されない。そのまま表示される
：き＞ジャンプ先        ジャンプしない。そのまま表示される
```

**全角でなければ効かない。**半角で書いても、エラーにならずその行が本文になる。

```
*トーク名      定義にならない。前の定義の本文として、そのまま表示される
$変数	5      代入されない。「$変数	5」と表示される
>ジャンプ先    ジャンプしない
_選択肢	行き先  選択肢にならない
```

半角 `*` で書いた定義は存在しないことになる。そのイベントは 204 を返す。

## 行のどこでも働く記号

`＃` と `：` は行頭でなくてよい。行の途中でも、そこから効きはじめる。

| 記号 | 意味 |
|---|---|
| `＃` | コメント。そこから行末までが消える |
| `：` | セリフ。書くたびにスコープが `\0` `\1` と入れ替わる |
| `<頭文字>：` | `characters.ini` があるときだけ。指定したキャラへ切り替える |

```
：あ＃ここから行末まで消える     → あ
＄変数	1＃コメント              → 1 が入る
```

どちらも全角のみ。半角の `#` `:` は効かず、そのまま表示される。

### 話者の切り替わり方

**里々は `：` の数で話者を決める。**書くたびに本体（`\0`）と相方（`\1`）が入れ替わる。

```
：あ：い：う          → \0あ \1い \0う
```

`＊` の本文は、相方側（`\1`）から始まる。

```
＊トーク
ここは相方が喋る。      ← ： を書かなかった行
：ここは本体。          \0
：ここは相方。          \1
```

**`：` を書かずに本文を始めると、本体と相方の両方にシェルが出る。**
セリフは必ず `：` から書く。

`＞` でジャンプすると、話者は `\0` に戻る。交互の数え方が引き継がれない。

```
＊トーク
：あ          \0
＞つぎ

＊つぎ
：い          \0   ← ジャンプしたので \1 にならない
：う          \1
```

括弧の展開（`（単語群名）` や `（call,…）`）では戻らない。`＞` だけ。

`\x`（クリック待ち）を置くと、そこで本体側に戻る。`\x[noclear]` は戻さない。

```
＊トーク
：本体が喋る。
：相方が喋る。
\x                  ← ここで本体側に戻る
このセリフは本体が喋っている。
```

### 話者を自分で指定する

`：` の代わりに、さくらスクリプトの `\0`（本体）`\1`（相方）を書いてよい。
里々は現在の話者を追っているので、混ぜても破綻しない。

```
＊トーク
：ひとつめ           \0
\1じぶんで指定       自分で書いた \1
：みっつめ           \0    直前が \1 なので、次の ： は \0 に戻る
```

`＠` の中では `：` が効かない（[展開した結果の中では効かない](#展開した結果の中では効かない)）。
単語群やユーザ関数にセリフを入れるなら、`\0` `\1` を書く。

```
＠セリフ群
\0本体のセリフ\1相方のセリフ
```

**`：` は行の数で話者が決まるので、条件分岐でセリフが増減すると入れ替わる。**
話者を固定したい箇所では `\0` `\1` を直接書く。

### 展開した結果の中では効かない

`：` が働くのは、辞書に直接書かれた行の中だけ。
`＠`／`（call,…）`／`（when,…）` の中に書いた `：` は、展開されるとただの文字になる
（[単語群の中では行頭記号が効かない](#単語群の中では行頭記号が効かない)）。
セリフを単語群やユーザ関数に入れるなら、`：` ではなく `\0` `\1` を書く。

`＃` にはこの制限が無い。`＠` の中でもコメントとして働く。

## 括弧

全角括弧が評価単位。中身によって意味が変わる。

| 中身 | 動作 |
|---|---|
| 数字 | サーフェス変更。`（５）` も `（5）` も `\s[5]` になる |
| 名前 | 該当する `＊`／`＠`／変数、または里々の組み込み関数に置き換わる |
| 名前,引数… | 組み込み関数の呼び出し |
| （空） | ランダムトークに置き換わる |

該当するものが無ければ、括弧ごとそのまま文字として残る。エラーにはならない。

辞書で定義できるのは `＊`（文）と `＠`（単語群）の2つだけ。
「関数」という定義の種類は無い。`when` や `calc` は里々が持っている組み込み関数で、
辞書側で増やすことはできない。処理を書いた `＊`／`＠` を `（call,…）` で呼べば、
関数のように使える。

半角括弧 `(…)` は評価されない。`(R0)` と書いても展開されず、そのまま表示される。

括弧は入れ子にでき、内側から順に展開される。

### 括弧の中の空白

**字下げはタブで行う。**括弧の中で無視されるのは、改行と、行頭のタブだけ。

```
（join
	,-
	,あ
	,い
）            → あ-い
```

半角スペースは無視されない。名前や引数の一部として扱われる。

```
（join
    ,-
    ,あ
    ,い
）            → （join    ,-    ,あ    ,い） がそのまま出る
```

`join    ` という名前の関数は無いので、括弧ごと文字として残る。エラーは出ない。
引数の側に付いた場合は、そのまま値に混ざる。

### 条件式の中だけは空白が無視される

式として計算される部分（`when` の第1引数、`＞` の条件、採用条件、`calc`）は、
空白を飛ばして解釈される。

```
（when,1 == 1,真,偽）        真
（when,あ == あ,真,偽）      真
```

関数の引数は文字列としてそのまま渡る。

```
（equal,あ ,あ）             0（偽）。第1引数は「あ 」
```

同じ括弧の中でも、**計算される場所と、文字列として扱われる場所で違う。**

括弧を文字として出したいときは `φ（` と書く
（[自動処理を止める記号 φ](#自動処理を止める記号-φ)）。

## 全角と半角

**里々は正規化しない。**どこが全角でどこが半角かは、要素ごとに決まっている。
間違えてもエラーは出ない。展開されずに文字として残るか、黙って別の値になる。

| 要素 | 書き方 |
|---|---|
| 里々の記号 `＊` `＠` `＄` `＞` `＿` `＃` `：` | 全角のみ |
| 評価の括弧 `（）` | 全角のみ |
| 関数名 | 半角小文字のみ。`WHEN` も `ｗｈｅｎ` も展開されない |
| 演算子 | どちらでもよい。`1＋2` と `1+2`、`＝＝` と `==` は同じ |
| 代入の `＝` | どちらでもよい |
| サーフェス指定の数字 | どちらでもよい。`（５）` も `（5）` も `\s[5]` |
| `（Ｒ０）` `（Ａ０）` `（Ｓ０）` `（Ｃ０）` | 英字・番号ともどちらでもよく、混ざってもよい（`（A０）` も動く）。ただし英字は大文字 |
| 上以外の組み込み変数の番号 | 半角のみ。`（サーフェス0）` は動き、`（サーフェス０）` は展開されない |
| 変数名・トーク名 | 書いたとおり。`＄Ａ` と `＄A` は別の変数になる |

`（r0）` は展開されない。Ｒ・Ａ・Ｓ・Ｃ は大文字で書く。

### 名前の一部を囲む記号も全角

`（変数「○○」の存在）` のカギ括弧は全角 `「」` のみ。

```
（変数「カウンタ」の存在）      1
（変数"カウンタ"の存在）        0
（変数『カウンタ』の存在）      0
```

**囲みを間違えても括弧は残らず、0 が返る。**未定義のときと同じ値なので、
「存在しない」と判断して先へ進んでしまう。

### 乱数の範囲は全角チルダ `～` のみ

```
（乱数0～9）    動く
（乱数0〜9）    波ダッシュ。「※　乱数の指定が変です　※」がその場に出る
（乱数0~9）     半角チルダ。同じ
```

見た目がほとんど変わらないうえ、エラーではなく文字列として画面に出る。
`（乱数）` のように範囲を書かない形は無い。

### 返る値の字種は、こちらでは決められない

| 書き方 | 返る |
|---|---|
| `＄カウンタ＝1＋2` | `３` 全角 |
| `（calc,1+2）` | `3` 半角 |

組み込み変数は変数ごとに違う。

| 全角で返る | 半角で返る |
|---|---|
| `（現在年）` `（現在月）` `（現在日）` `（現在時）` `（現在分）` `（現在秒）` | `（Ｒの数）` `（Ｓの数）` |
| `（起動秒）` `（累計秒）` `（最終トークからの経過秒）` | `（サーフェス0）` `（文「○○」の数）` |
| `（単語群「○○」の数）` `（起動しているゴースト数）` | `（変数「○○」の存在）` などの 0／1 |

乱数だけは、書いたほうに合わせて返る。

```
（乱数0～9）      → 3
（乱数０～９）    → ７
```

数値として計算するぶんには、どちらでも同じに扱われる（[条件式](#条件式)）。
画面に出すときだけ問題になる。揃えるなら `（zen2han,…）` `（han2zen,…）` を通す。
どちらも英数字をまとめて変換する（`（han2zen,2026nen）` → `２０２６ｎｅｎ`）。

## 変数

```
＄カウンタ	5              代入
（カウンタ）                  参照
（set,カウンタ,5）             関数形式の代入
```

- 型はない。すべて文字列として扱われ、必要に応じて数値として解釈される
- **未定義の変数を参照しても空にならない。** `（カウンタ）` という文字列がそのまま出る。
  存在確認には `（変数「カウンタ」の存在）` を使う

代入は、名前の直後に区切りが要る。

| 書き方 | |
|---|---|
| `＄名前＝式` | 代入される。右辺を計算する |
| `＄名前=式` | 同じ（半角の = も有効） |
| `＄名前<TAB>値` | 代入される。右辺を計算しない |
| `＄名前 ＝ 値` | **代入されない。**`＝` の手前に空白を置くと無効 |

計算するかどうかで、同じ式が別の結果になる。

```
＄カウンタ＝（カウンタ）＋１       １ → ２ → ３ と増える
＄カウンタ<TAB>（カウンタ）＋１     式が文字列として入り、呼ぶたびに伸びる
```

→ [数を増やす代入](#数を増やす代入)

### システムから渡される値

| 記法 | 中身 |
|---|---|
| `（Ｒ０）` `（Ｒ１）`… | SHIORI イベントの Reference0, Reference1… |
| `（Ｓ０）` `（Ｓ１）`… | `split` や SAORI の配列戻り値 |
| `（Ａ０）` `（Ａ１）`… | ユーザ関数（`call`）に渡された引数 |
| `（Ｃ０）` `（Ｃ１）`… | `times` / `for` / `while` のループカウンタ。**番号は入れ子の深さ**（下記） |
| `（Ｒの数）` `（Ａの数）` `（Ｓの数）` | それぞれの個数。半角で返る |

- 番号は 0 から始まり、2桁以上も書ける（`（Ｒ１０）`）。`（Ｒ０）` しか無いわけではない
- `（Reference0）` という書き方では受け取れない。`（Ｒ０）` と書く
- 英字・番号とも全角半角どちらでもよく、混ざってもよい。
  `（Ａ０）` `（A0）` `（Ａ0）` `（A０）` はすべて同じものを指す
- 英字は大文字のみ。`（r0）` は展開されず、そのまま文字として出る

### ループカウンタの番号は入れ子の深さ

Ｒ・Ｓ・Ａ の番号は「何番目の値か」。Ｃ の番号だけは「入れ子の深さ」。

`（Ｃ０）` が今いるループ、`（Ｃ１）` が1つ外側、`（Ｃ２）` がその外。

```
（for,1,2,外（Ｃ０）-（for,3,4,内（Ｃ０）親（Ｃ１）;））

→ 外1-内3親1;内4親1;外2-内3親2;内4親2;
```

内側のループから外側のカウンタを読むには `（Ｃ１）` を使う。
`（Ｃ１）` は「2番目のループカウンタ」ではない。

`loop` のカウンタはこの形ではなく `（<呼び先の名前>カウンタ）`（[繰り返し](#繰り返し)）。

**変数名に `A0` `R0` `C0` `S0` を使わない。**同じ名前の変数を作っても、
参照した時点でこちらが優先され、値は空になる。エラーは出ない。

## 特殊変数

名前が決まっている変数が2種類ある。用途が違うので混同しない。

| | 使い方 | 役割 |
|---|---|---|
| 情報取得変数 | `（現在時）` と読む | 里々やシステムの状態が返る |
| 特殊変数 | `＄自動挿入ウェイトの倍率` へ書く | 里々の動作そのものが変わる |

どちらも、自分で作る変数と同じ名前空間にある。同じ名前を付けると動作が変わる。

以下はどちらも**代表例で、これで全部ではない。**
全量は里々 Wiki の「特殊変数」「情報取得変数」にある。仕様を引く。
どちらも項目ごとに分かれているので、名前が分かっていればその名前で引く。

MCP があるなら `source="satori_wiki"`、query は `情報取得変数` か `特殊変数`。

### 読むもの

| 変数 | 返るもの |
|---|---|
| `（現在年）（現在月）（現在日）（現在曜日）（現在時）（現在分）（現在秒）` | 日付と時刻。曜日は「日」「月」…の1文字 |
| `（起動時）（起動分）（起動秒）` `（累計時）（累計分）（累計秒）` | 今回の起動からの経過時間と、累計の起動時間 |
| `（起動回数）` | 「SHIORI が読み込まれた回数」。起動した回数ではない |
| `（最終トークからの経過秒）` | 直前のトークからの秒数 |
| `（乱数1～10）` | 範囲内の整数 |
| `（サーフェス0）（サーフェス1）` | 現在のサーフェス番号 |
| `（文「○○」の存在）（単語群「○○」の存在）（変数「○○」の存在）` | 1 か 0 |
| `（文「○○」の数）（単語群「○○」の数）` | 定義されている数 |
| `（ID）` | いま処理しているイベント名 |
| `（Sender）（Charset）` | リクエストのヘッダ |
| `（Status）` | いまの実行状態。喋っている最中かなど（下記） |
| `（里々のバージョン）` | 例：`phase Mc171-4` |
| `（pwd）` | `satori.dll` のあるフォルダ。末尾に `\` が付く |
| `（本体の所在）` | ベースウェアのフォルダ |
| `（起動しているゴースト数）（隣で起動しているゴースト）` | 同時起動の状況 |
| `（予約トーク数）` | `＄次のトーク` で予約されている数 |
| `（選択ＩＤ）（選択ラベル）（選択番号）` | 直前に選ばれた選択肢。条件がある（下記） |

### テスターでは本物の値が返らないもの

ベースウェアが持っている情報は、テスターでは揃わない（→ `testing.md`）。
**展開されないものより、値が返るもののほうが危うい。**取れたように見える。

| 変数 | テスターでの挙動 |
|---|---|
| `（Status）` | 展開されない。`（Status）` という文字列がそのまま残る |
| `（get_property,…）` | 常に空が返る。第2引数に書いた「失敗時の値」も返らない。別の手段で取れる（下記） |
| `（Sender）（Charset）` | テスターが名乗った値が返る。SSP が送ったものではない |
| `（本体の所在）` | テスターを動かしたプログラムの場所が返る。SSP の場所ではない |
| `（起動しているゴースト数）（隣で起動しているゴースト）（導入済みゴースト「○○」の存在）` | SSP がいない前提の値が返る。同時起動も導入済みも無いものとして扱われる |

SSP で動かさないと本当の値は分からない。テスターの中では確かめようがない。

- **返る値を決め打ちした分岐を書かない**
- 値そのものではなく、空かどうかで判断できる形にする

### プロパティの値は Get-GhostInfo.ps1 で取る

`（get_property,…）` がテスターで空になっても、値そのものは取れる。
`Get-GhostInfo.ps1` が起動中の SSP に直接問い合わせる（→ `testing.md`）。

SSP が起動していて、対象のゴーストが動いていることが条件。
止まっていれば取れないので、そのときは起動を頼む（→ `dialogue.md`「取れないものは、頼む」）。
**遠慮して推測で埋めない。**

### `（Status）` ── いまの実行状態

SSP が送ってくるヘッダを、そのまま返す。何も無ければ空。

| 値 | |
|---|---|
| `talking` | スクリプトを実行中。`\e` に達すると解除 |
| `choosing` | 選択肢を表示中。`＿` から作った `\q` も含む |
| `timecritical` | `\t` の影響下。新しいイベントが起きるか、選択肢の無い状態で喋り終わると解除 |
| `passive` | `\![enter,passivemode]` 中 |
| `induction` | `\![enter,inductionmode]` 中 |
| `nouserbreak` | `\![enter,nouserbreak]` 中 |
| `minimizing` | 最小化中 |
| `online` | ネットワーク通信中 |
| `opening(種類)` | 入力ボックスなどが開いている。複数なら `/` 区切り |
| `balloon(ID=n/…)` | 表示中のバルーン。`(0=0)` なら本体側が0番 |

**複数あるときはカンマでつながる。**したがって `（equal,…）` や `==` では比べられない。
`（count,（Status）,talking）` が1以上かで判定する。

```
choosing,balloon(0=0)      選択肢を出していて、本体側が0番のバルーンを表示中
```

値は、そのイベントが届いた時点のものである。処理している間に変わることはない。
**繰り返し読んで進み具合を追うことはできない**（→ `capabilities.md`「実行の途中には手を出せない」）。

### 選択肢変数が入る条件

`（選択ＩＤ）（選択ラベル）（選択番号）` が更新されるのは、
里々が ID を書き換えた選択肢を選んだときだけ。

| ID | 更新 | `（選択ＩＤ）` に入るもの |
|---|---|---|
| `＿えらぶ`（ID は選択肢名） | される | `えらぶ` |
| `＿えらぶ<TAB>ジャンプ先` | される | `ジャンプ先` |
| `\q[えらぶ,ID]` | される | `ID` |
| `On` で始まる ID | されない | ─ |
| `script:` で始まる ID | されない | ─ |
| `\__q[ID]えらぶ\__q` | されない | ─ |

`On` で始まる ID を使うと、選択肢変数は使えない。
SSP がその名前のイベントを直接起こすので、里々の選択肢処理を通らない。

**更新されないとき、変数は空にならない。前に選んだ値がそのまま残る。**
一度も選んでいなければ未定義で、`（選択ＩＤ）` という文字列が画面に出る。

里々が ID に何をしているかは `internals.md` の「選択肢の ID 書き換え」。

### 書くもの

代入した瞬間に効く。多くは、以後のトークにも効き続ける。

| 変数 | 効果 |
|---|---|
| `＄引数区切り追加` `＄引数区切り削除` | 引数の区切り文字を足す・戻す |
| `＄トーク開始時` `＄トーク終了時` | 全トークの前後に文字列を足す |
| `＄選択肢開始時` `＄選択肢終了時` | 選択肢1つずつの前後に文字列を足す |
| `＄スクリプトの一番頭` | 応答の先頭に文字列を足す |
| `＄自動挿入ウェイトタイプ` `＄自動挿入ウェイトの倍率` | 自動ウェイトの種類と長さ（[自動で入るウェイト](#自動で入るウェイト)） |
| `＄文「○○」の重複回避` `＄単語群「○○」の重複回避` | 同じものを続けて選ばない数 |
| `＄デフォルトサーフェス0` `＄会話時サーフェス戻し` | トークの先頭に入るサーフェスと、その挿入の有無（[先頭に挿入されるスコープとサーフェス](#先頭に挿入されるスコープとサーフェス)） |
| `＄次のトーク` `＄次から○回目のトーク` | トークを予約する |
| `＄○○タイマ` `＄全タイマ解除` | 後で `＊○○` を実行する |
| `＄辞書フォルダ` | 読む辞書のフォルダを差し替える（下記） |
| `＄辞書リロード` | 代入した時点で実行される |

**装飾系（`＄トーク開始時` `＄デフォルトサーフェス0` など）を条件つきで使うなら、
要らなくなった時点で空に戻す。**戻さないと、関係ないトークにまで付き続ける。

**タイマは秒を計っていない。**`＄○○タイマ	2` は「OnSecondChange を2回受けたら」の意味で、
このイベントが来ない間は進まない。

タイマの残りはセーブされる。変数なので、他の変数と同じように保存される。
動いている途中で終了すると、次の起動で残りから再開する。
終了時にリセットしないと、**起動した直後にいきなり発火する**
（→ `internals.md`「里々独自の起動・終了イベント」）。

### ＄辞書フォルダ

読む辞書のフォルダを丸ごと差し替える。多重人格や、複数ゴーストでの辞書の共有に使われる。

```
＄辞書フォルダ	other       other\ の dic*.txt に入れ替わる
＄辞書フォルダ	.           元に戻す
＄辞書フォルダ	.,common    カンマ区切りで複数指定。両方の定義が使える
```

指定するのは `satori.dll` のあるフォルダからの相対パス。
絶対パスを書くと基準パスの後ろに連結され、そのフォルダは見つからない。
**辞書が1つも読まれなくなり、以後の応答が全部 204 になる。**エラーは出ない。

**実行すると、里々が一度終了して読み込み直す。**セーブが走り、
`OnSatoriUnload` → `OnSatoriLoad` → `OnSatoriBoot` が流れ、起動回数が増える。
差し替える前のフォルダの定義は、読まれなくなる。

### 起動時に差し替えるなら ＊初期化

`＊初期化` は `satori_conf.txt` に書く。里々はこれを、辞書を読み込む前に実行する。

```
satori_conf.txt → ＊初期化 → セーブデータ → dic*.txt → OnSatoriLoad → OnSatoriBoot
```

- `＠初期化` では呼ばれない。里々が探すのは `＊`（文）の「初期化」だけ
- `dic*.txt` に書いても呼ばれない。そこを読むより前に実行される

どちらもエラーにならない。**書いた設定が黙って無視される。**

## 条件式

条件は3か所に書ける。どれも採用に影響する。

```
＊トーク名	（進行度） >= 3              定義行。タブ区切りの採用条件
＞ジャンプ先	（天気） == 晴れ             ジャンプするかどうか
（when,（好感度） > 10,真の結果,偽の結果）    本文中。値を差し替える
```

**定義行だけ見て「条件が付いていない」と判断しない。**

演算子は半角・全角のどちらでも書ける。

| 種類 | 演算子 |
|---|---|
| 四則 | `+` `-` `*` `/` `%`（`＋` `－` `×` `÷` `％`） |
| 比較 | `==` `!=` `<` `>` `<=` `>=` |

論理演算子は `&&` `||` `!` の3つ。

### 真偽の決まり方

条件式は、次の順で処理される。

```
括弧を展開する
  → 式として計算する
  → 全角数字を半角に直す
  → 先頭から数値として読めるところまで読む（読めなければ 0）
  → 0 以外なら真
```

最後の2段が C の `strtol` そのもの。途中で数値でない文字が来たら、そこで止まる。

| 書いたもの | 読まれ方 | 判定 |
|---|---|---|
| `0` `00` `-0` | 0 | 偽 |
| `1` `2` `-1` | そのまま | 真。負の数も真 |
| `0.5` | `0` で止まる → 0 | 偽。小数は書けない |
| `１`（全角） | 半角に直って 1 | 真 |
| `0１` | `01` → 1 | 真 |
| `1あ` | `1` で止まる → 1 | 真 |
| `あ1` `あ` | 先頭が数値でない → 0 | 偽 |
| 空白だけ | 0 | 偽 |
| 条件式を書かない | ─ | 常に採用 |

**「空でなければ真」ではない。**文字列は数値として読めないので偽になる。

`＝` による代入の結果は全角で返る。入口で半角に直し、出口で全角に戻している。
`＄変数＝式` の結果が `１` `２` のような全角数字になるのはこのため。
同じ計算でも `（calc,…）` は半角で返る（[全角と半角](#全角と半角)）。

```
＊トーク名	（名前）               （名前）が「さくら」なら偽。常に採用されない
＊トーク名	（変数「名前」の存在）    1 か 0 が返るので意図どおり動く
```

## フロー制御

行頭記号で書く形と、括弧の関数で書く形がある。どちらも現役で、
古い辞書ほど行頭記号だけで書かれている。
既存の辞書がどちらで書かれているかを見て、それに合わせる。

### 分岐

```
＞ジャンプ先	（天気） == 晴れ        行頭記号。条件が真ならそのトークへ移る
（when,（天気） == 晴れ,真,偽）         関数。その場に結果を置く
```

`＞` はそこで移動する。`when` は値を返す。
セリフを丸ごと切り替えるなら `＞`、文の一部を差し替えるなら `when`。

**ジャンプ先が無ければ、その行を飛ばして次の行へ進む。**エラーにはならない
（内部ログに `＞名前 not found.` として残る）。

### 繰り返し

| 書き方 | ループ本文 | カウンタ | 途中で抜ける |
|---|---|---|---|
| `＞` によるジャンプ | 別の `＊` | 自分で変数を用意 | 条件を外す |
| `（loop,名前,回数）` | 別の `＊`／`＠` | `（<名前>カウンタ）` | 不可 |
| `（times,回数[,初期値],本体）` | 引数の中 | `（C0）` | 不可 |
| `（for,開始,終了[,増分],本体）` | 引数の中 | `（C0）` | 不可 |
| `（while,条件[,初期値],本体）` | 引数の中 | `（C0）` | 条件で抜ける |

- `loop` のカウンタは `（C0）` ではない。`＊犬` を回すなら `（犬カウンタ）`
- 開始値が違う。`（loop,犬,3）` のカウンタは 1,2,3、
  `（times,3,…）` の `（Ｃ０）` は 0,1,2。`for` は書いた開始値から
- `loop` の第1引数に括弧を付けない。`（loop,犬,3）` と書く
- `loop` は範囲でも書ける。`（loop,名前,開始値,終了値[,増分]）`
- ループが入れ子のとき、1つ外側のカウンタは `（Ｃ１）`、その外は `（Ｃ２）`
  （[ループカウンタの番号は入れ子の深さ](#ループカウンタの番号は入れ子の深さ)）
- **`times` / `while` / `for` に、括弧で作った区切り文字を渡さない**
  （[展開を遅らせる関数に…](#展開を遅らせる関数に括弧で作った区切り文字を渡さない)）

ジャンプで繰り返す形：

```
＊順に読む
＄カウンタ＝（カウンタ）＋１
＞その（カウンタ）
＄カウンタ＝（カウンタ）－１
：もうありません。

＊その１
：1つめ。
```

`＞その（カウンタ）` はジャンプ先の名前を計算で作っている。
ジャンプ先が無ければ次の行へ進むので、それが終了条件になる。

### 選択肢

```
＿選択肢名	ジャンプ先         行頭記号。里々が \q に変換する
\q[表示文字,ID]                 さくらスクリプトを直接書く
\__q[ID]…\__q                  範囲を選択肢にする。画像も選択肢にできる
```

画像や装飾を選択肢に含めたいときは、さくらスクリプトを直接書く。

ID の付け方で、選んだ後の流れが変わる。

| ID | 選んだあと | 引数 |
|---|---|---|
| ふつうの文字列 | 里々が `＊その名前` へ飛ばす | 渡せない |
| `On` で始まる | その名前のイベントが直接起きる | `（Ｒ０）` 以降で受け取る |

`＿選択肢名<TAB>ジャンプ先` はふつうの文字列になるので、
ジャンプ先のトークを書いておけば動く。`＊OnChoiceSelect` は要らない。

選んだときに値を渡したいなら `On` で始める。

```
\q[はい,OnAnswer,yes,1]

＊OnAnswer
：（Ｒ０）を選んだ（（Ｒ１）番目）
```

`On` で始めると里々の選択肢処理を通らないので、
`（選択ＩＤ）` などの選択肢変数は更新されない
（[選択肢変数が入る条件](#選択肢変数が入る条件)）。

`OnChoiceSelectEx` で受ける書き方もある → `internals.md`「選択肢の ID 書き換え」

## 関数

```
（関数名,引数1,引数2）
```

**関数名は半角小文字で書く。**`（WHEN,…）` も `（ｗｈｅｎ,…）` も展開されず、
括弧ごと文字として画面に出る。

- 日本語名の関数もある。`（単語の追加,単語群名,単語）` `（バイト値,1）` など
- SAORI 呼び出しも同じ形。`（<登録名>,関数名,引数…）`。戻り値は `（Ｓ０）` で受ける

### よく使う関数

代表例で、一覧ではない。里々の関数はこの倍以上ある。
**ここに無いことを「無い」と言わない。**引き方は[下記](#一覧は里々-wiki-から引く)。

| 用途 | 書式 | |

| 分岐 | `（when,条件,真,偽）` | 選ばれなかった枝を実行しない、数少ない関数 |
| 多分岐 | `（whenlist,左辺,右辺1,結果1,…,既定値）` | 左辺と右辺を文字列として連結してから条件式として評価する |
| 計算 | `（calc,式）` | 整数に丸める。未定義の変数を扱えない |
| 計算（小数） | `（calc_float,式）` | |
| 代入 | `（set,名前,値）` | 右辺を計算しない |

| ゆるい比較 | `（compare,A,B）` | どちらも同一視する。`ABC` と `ａｂｃ` が一致する |

### call ── ユーザ関数

**辞書で定義できるのは `＊`（文）と `＠`（単語群）だけ。**「関数」という定義の種類は無い。
処理を書いた定義を `（call,…）` で呼ぶと、関数のように使える。

```
（call,名前,引数1,引数2）
```

- 引数は呼び先で `（Ａ０）` `（Ａ１）`… として受ける。個数は `（Ａの数）`
- **呼び先は `＠`（単語群）にする。**`＊` を呼ぶと、自動挿入された改行・ウェイト・
  スコープが戻り値に混ざる（[定義](#定義)）
- 呼び先に処理を並べて書かない。`＠` は1行が1候補なので、1行しか実行されない

```
＊
：（call,足し算,100,2）

＠足し算
（Ａ０）たす（Ａ１）は（han2zen,（calc,（Ａ０）＋（Ａ１）））です
```

### vncall ── 引数を名前で渡す

引数を「値」ではなく「変数名」で渡す。呼び先には、その変数の中身が `（Ａ０）` として入る。

`vncall` には「最初に引数を区切った後は、それ以降引数を区切らない」というルールがある。
値の中にカンマや読点が入っていても、そこで割れない。

呼ぶ相手は2つに絞る。

1. `split` のように、引数の区切りが問題になる組み込み関数
2. 自作の `＊`／`＠`

```
＄入力	あ,い,う
＄区切り	,

（vncall,split,入力,区切り）    「,」で3つに分割できる

（call,処理,（入力））           （Ａ０）は「あ」。値が割れて（Ａの数）は 3
（vncall,処理,入力）             （Ａ０）は「あ,い,う」。（Ａの数）は 1

＠処理
受け取ったもの（Ａ０）
```

外部から来た文字列を、割られずに渡せる唯一の形（[引数区切りの誤爆](#引数区切りの誤爆)）。

**ただし括弧の展開は防げない。**値の中の `（…）` は `call` と同じように展開される
（[外部から来た文字列は、関数に渡した時点で展開される](#外部から来た文字列は関数に渡した時点で展開される)）。
区切りの問題だけが解決する。

**展開を遅らせる関数（`when` `whenlist` `times` `for` `while`）を `vncall` で呼ばない。**
サポートされていない。条件式がそのまま画面に出たうえ、枝が両方実行される。
エラーは出ず、`when` を書いたのに `if` と同じ結果になる。

そこを開けば全部が並ぶ。特殊変数と情報取得変数も、それぞれ1ページにまとまっている。

## 無い機能と、その代わり

**無いことだけを知ると「できない」と判断してしまう。代わりに何があるかまで見る。**

### データ

| やりたいこと | 里々では |
|---|---|
| 配列を使う | 無い。`（split,文字列,区切り）` で分割して `（Ｓ０）` `（Ｓ１）`… で受ける |
| 配列の要素数 | `split` の戻り値が分割数 |
| 連想配列 | 無い。変数名を組み立てて代用する |
| ローカル変数 | 無い。ユーザ関数の引数 `（Ａ０）` を使うか、命名規約で区別する |
| 変数のスコープ | 無い。すべてグローバルで、終了時に保存される |
| 変数が存在するか | `（変数「名前」の存在）`。`is_empty` はシステム変数用 |
| 数値と文字列の区別 | 無い。すべて文字列で、必要に応じて数値として解釈される |

動的な変数名。括弧が内側から展開される性質を使い、変数名そのものを組み立てられる。

```
（Ａ（Ａ０））              （Ａ０）が 3 なら （Ａ３）を参照する
（set,フラグ（Ｃ０）,1）     ループカウンタごとに別の変数へ書く
```

配列や連想配列の代わりに使われる、里々の常套手段。

### 制御

| やりたいこと | 里々では |
|---|---|
| 多分岐 | `（whenlist,左辺,右辺1,結果1,…,既定値）`。右辺に演算子を含めて書く |
| break | `for` / `times` / `loop` には無い。`while` かジャンプで書く |
| 関数定義 | `＠名前` を書き、`（call,名前,引数…）` で呼ぶ。引数は `（Ａ０）` |
| 早期リターン | 無い。`＞ジャンプ先` で別のトークへ飛ばす |

**「見つかったら止める」形の探索を `for` で書き始めると、後から行き詰まる。**
途中で抜ける必要があるなら、最初から `while` かジャンプで書く。

### 文字列

| やりたいこと | 里々では |
|---|---|
| 厳密に比較する | `（equal,A,B）` |
| 大文字小文字を無視して比較 | `（compare,A,B）`（半角全角も同一視される） |
| 前方一致・後方一致 | `（compare_head,…）` `（compare_tail,…）` |
| 含まれるか調べる | `（count,文字列,検索文字列）` が 1 以上か |
| 置換・削除 | `（replace,…）` `（erase,…）` |
| 分割・連結 | `（split,…）` → `（Ｓ０）`… ／ `（join,区切り,…）` |
| 文字数・N文字目・部分文字列 | `（length,…）` `（at,…）` `（substr,…）` |
| 正規表現 | 無い。SAORI に頼る |

### 計算

| やりたいこと | 里々では |
|---|---|
| 計算する | `（calc,式）`。小数が要るなら `（calc_float,式）` |
| 乱数 | `（乱数０～９）`。範囲の区切りは全角チルダ `～` のみ |
| ランダムに1つ選ぶ | `（choice,A,B,C）`、または同名の `＊`／`＠` を複数書く |

### 入出力

| やりたいこと | 里々では |
|---|---|
| イベントを受ける | `＊イベントID` を定義する。引数は `（Ｒ０）`… |
| リソースを返す | `＠リソース名`（`homeurl` など） |
| SSP の情報を取る | `（get_property,プロパティ名,失敗時の値）` |
| 別のイベントを起こす | `\![raise,イベント名,引数]` を出力する |
| ファイル操作 | ほぼ無い（`mkdir` `lsimg` 程度） |

### SAORI に頼る

里々単体でできないことは、SAORI（外部 DLL）に渡す。

- 正規表現
- ファイルの読み書き
- 音声ファイルの再生
- 並べ替えなど、繰り返しの多い処理

**配布物に DLL の同梱が必要になる。**利用者に追加のダウンロードを求めることになるなら、
着手する前に伝える。

## 文字コード

- 辞書の文字コードは `satori_bootconf.txt` の `is_utf8_dic,true`（辞書だけ）か
  `is_utf8_all,true`（全体）で UTF-8 になる。**どちらも無ければ Shift_JIS として読まれ、
  UTF-8 で書いた辞書は定義ごと認識されない**（エラーは出ず、応答が 204 になる）
- SHIORI の通信とログは Shift_JIS
- 全角と半角は別物。里々は正規化しない。検索するときも、辞書に書かれているとおりの
  表記で探す。どこが全角でどこが半角かは [全角と半角](#全角と半角)
- 空白は削られない。行頭・行末の空白はそのまま残る（`trim` は行われない）。
  `：[あ   ]` は `[あ   ]` と出る。
  `＄名前 ＝ 値` が代入にならないのも同じ理由で、名前の直後に空白があると
  `＝` が区切りとして認識されない。
  例外は括弧の中の行頭タブだけ（[括弧の中の空白](#括弧の中の空白)）

## 壊れるところ

**どれもエラーにならない。**動いたまま、結果だけが違う。
半分は「括弧が内側から展開され、結果が構文として読み直される」に帰着する。

### 枝を選ぶ関数の多くは、両方の枝を実行する

括弧が内側から展開されるため、条件を評価する時点で枝は実行済みになっている。

```
（if,（天気）== 晴れ,（set,気分,1）,（set,気分,0））
```

`set` が両方走り、後から実行された `（set,気分,0）` が残る。条件に関係なく `気分` は 0。

**展開を遅らせるのは、分岐では `when` と `whenlist` だけ。**

| 関数 | 選ばれなかった枝 |
|---|---|
| `when` `whenlist` `times` `for` `while` | 実行されない |
| `if` `iflist` `unless` `switch` `nswitch` `choice` | **実行される** |

戻り値はどれも正しい。枝が単なる文字列なら違いは出ない。
だが**後から枝に処理を足した時点で、黙って壊れる。**
**使い分けの基準を持たず、常に `when` と `whenlist` を使う。**

| やりたいこと | 書き方 |
|---|---|
| 二分岐 | `（when,条件,真,偽）` |
| 偽のときを先に書きたい | `when` の枝を入れ替える。`unless` は使わない |
| 多分岐 | `（whenlist,左辺,右辺1,結果1,…,どれでもないとき）` |
| 数値で分岐 | `whenlist` の右辺を `==1` `==2` にする。`nswitch` `switch` は使わない |
| 文字列で分岐 | `（when,（equal,…）,…）` を重ねる。条件式で文字列を比べない |

`whenlist` は左辺と右辺を文字列としてつなぎ、つないだ全体を条件式として評価する。
演算子はどちらに書いてもよい。

```
（whenlist,（好感度）,>10,親しい,>5,ふつう,よそよそしい）
        → 「（好感度）>10」「（好感度）>5」を順に評価する

（whenlist,（進行度）!,=1,一でない,=2,二でない,どちらでもない）
        → 「（進行度）!=1」「（進行度）!=2」を順に評価する
```

左辺に条件式を丸ごと書き、右辺を空にしても動く。
**「左辺＝比べる値、右辺＝比べ先」と決めてかからない。**既存の辞書では、
演算子が左辺の末尾に付いていることがある。

`switch` は `左辺==右辺` を自動で組むので演算子が要らない。
その1点だけのために、枝が全部実行される関数を選ばない。

### 展開を遅らせる関数に、括弧で作った区切り文字を渡さない

**`when` `whenlist` `times` `for` `while` では、引数区切りを括弧から出力してはいけない。**

```
（when（バイト値,1）（天気）== 晴れ（バイト値,1）（set,気分,1）（バイト値,1）（set,気分,0））
```

遅延は、区切り文字がそこに直接書かれていることが前提。
区切りを作る括弧の展開も遅れるため、区切りと認識されない。

- `when` は `if` と同じ挙動になり、枝が両方実行される
- `for` `times` `while` は回数どおり回るが、`（Ｃ０）` が空になる

どちらもエラーは出ない。`for` は空の値でループし続ける。

区切りに使うバイト値は直接書くか、`replace.txt` で別名を定義しておく。

### 引数区切りの誤爆

区切り文字は `,` `，` `、` `､` と 0x01 のすべてが有効。
引数の中にこれらが入ると、そこで切られる。

```
（関数名,test,\q[テスト,OnTest]）    \q の中のカンマで切られる
（関数名、test、\q[テスト,OnTest]）  読点を区切りにすれば安全
```

引数にどの区切り文字も含まれうる場合（ファイル名など）は、
`＄引数区切り追加` で使われていない文字を一時的に登録する。どんな文字でも指定できる。

```
＄引数区切り追加	山
（when山（変数）==1山あたり山はずれ）
```

**選択肢を含むトークを引数に渡せない。**`＿` や `\q[…]` があると、
里々が内部処理で 0x01 を必ず挿入する。トーク全文を関数へ渡す場合、
区切りに `,` `、` だけでなく 0x01 も使えない。

引数を変数名で渡す `vncall` は、この制約を受けない（[関数](#関数)の `vncall`）。
ただし括弧の展開は防げない。区切りの問題だけが解決する。

### 外部から来た文字列は、関数に渡した時点で展開される

ユーザー入力・ファイル名・SAORI の戻り値に全角 `（）` が含まれていると、
里々がそれを構文として解釈する。**境界は「関数に渡したかどうか」。**

里々は外部から来た文字列を変数に入れるとき、括弧を `φ（` の形で保護する。
保護は変数から変数へ写す間は続く。関数の引数にすると外れる。

```
（Ｒ０）                        そのまま出す          展開されない
＄名前<TAB>（Ｒ０）
（名前）                        タブで代入して読む    展開されない
＄別名<TAB>（名前）
（別名）                        変数から変数へ写す    展開されない（何度でも）
（set,名前,（Ｒ０））             set で代入する        展開されない

＄名前＝（Ｒ０）                 ＝ で代入する         展開される
（replace,（Ｒ０）,あ,い）       関数に渡す            展開される
（replace,（名前）,あ,い）       変数を経由しても      展開される
```

**外部から来た文字列は、必ずタブか `set` で代入する。**

置換が起きなくても展開される。対象の文字列が含まれていない `replace` を
通しただけでも保護は外れる。変数に退避しても安全にはならない。

守り方は2つ要る。

1. 引数の区切りを 0x01 にする ── 引数の分割は、中の括弧を展開した後に行われる。
   入力に `,` や `、` が含まれていると、そこで引数が割れる
2. 最初の置換で全角括弧を半角に潰す ── 置換の対象になる時点では、括弧はまだ文字のまま。
   先に潰しておけば、戻り値が展開されても構文にならない

順序が要点。`\` の置換だけを書くと、その戻り値が展開されて中の記法が実行される。
`\` は SSP がさくらスクリプトとして解釈するのを止めるためのもので、
**里々の括弧展開は止まらない。**層が違う。

```
入力  あ,い（乱数0～99）\s[0]

両方を守った場合         あ,い(乱数0～99)\\s[0]
区切りが , や 、          引数の個数が正しくありません。
\ の置換だけ              あ,い83\\s[0]        ← 里々が乱数を実行した
```

セーブを経ると元に戻らない。

| 含まれる文字 | セーブデータ | 次回起動後 |
|---|---|---|
| `（` `）` | `φ（` にエスケープされる | 元の文字列に戻らない |
| `＃` | そのまま書き出される | 行がコメントになり、変数ごと消える |

どちらもエラーにならない。**外部から来た文字列を、加工せずに保存しない。**

### 同じ採用条件は1回しか評価されない

同名のトークが複数あるとき、候補を選ぶ前に採用条件がまとめて展開される。
このとき**同じ記述の括弧は1回だけ評価され、その結果が全候補で共有される。**

```
＊挨拶	（乱数0～1）
：おはよう

＊挨拶	（乱数0～1）
：こんにちは
```

候補ごとに抽選するつもりで書いても、どれも同じ値になる。
0 なら全部落ちて 204、1 なら全部残る。絞り込みにならない。

`（call,…）` や `＠` の呼び出しでも同じで、呼び出し自体が1回しか起きない。

記述が違えば別々に評価される。`（乱数0～1）` と `（乱数0～2）` は別のものとして扱われる。

本文中の括弧は毎回評価される。この挙動は採用条件に限る。

候補ごとに違う判定をしたいなら、条件式の記述そのものを変えるか、
1つのトークにまとめて本文側で分岐する。

### 数を増やす代入

| 書き方 | 初期値なし | 初期値あり |
|---|---|---|
| `＄カウンタ＝（カウンタ）＋１` | １ → ２ → ３ | 正しく増える |
| `＄カウンタ<TAB>（カウンタ）＋１` | `（カウンタ）＋１＋１` と伸びる | `0＋１＋１` と伸びる |
| `＄カウンタ＝（calc,（カウンタ） + 1）` | `カウンタ51` と壊れる | 正しく増える |
| `（set,カウンタ,（calc,（カウンタ） + 1））` | `カウンタ11` と壊れる | 1 → 2 → 3 |
| `（set,カウンタ,（カウンタ） + 1）` | 式が文字列として伸びる | 同じ |

**未定義の変数を 0 として扱うのは `＝` の右辺だけ。**
`calc` は未定義を扱えず、変数名の一部が値に混ざる。

タブ区切りと `set` は右辺を計算しない。式がそのまま文字列として入り、
呼ばれるたびに伸び続ける。エラーは出ず、`（変数「カウンタ」の存在）` も 1 を返す。

`calc` や `set` で増やすなら、起動時のイベントで `＄カウンタ<TAB>0` と初期値を入れる。

### 変数・単語群・トークは名前空間を共有する

同じ名前を付けると、**片方が優先され、もう片方は読めなくなる。**

```
＠あいさつ
単語群の中身

＄あいさつ＝変数の中身
（あいさつ）                → 単語群の中身
```

変数は設定されている。セーブデータにも入る。だが読めない。

```
（変数「あいさつ」の存在）      → 1
（単語群「あいさつ」の存在）    → 1
```

**どちらも「存在する」と返るので、存在確認では気づけない。**
「セーブされているのに反映されない」という形の不具合になる。
名前は長めに、役割が分かる形で付ける。

数字も同じ名前空間にある。`（２０）` はサーフェス指定だが、
`＠２０` を定義するとそちらが優先され、`\s[20]` にならない。

```
＠２０
なにか

（２０）    → なにか
```

番号で管理する設計（`＠1` `＠2` …）を作ると、その番号のサーフェス指定が消える。
**定義の名前に裸の数字を使わない。**

里々は一部のイベントを自分で処理している。なで反応もランダムトークもタイマも、
辞書に何も書かなくても動くのはそのため。
**同じ名前のトークを定義すると、その処理が止まる。**

| 定義すると | 止まるもの |
|---|---|
| `＊OnSecondChange` | **ランダムトークと `＄○○タイマ` の両方** |
| `＊OnMouseMove` | なでられ反応（`＊0Headなでられ` など） |
| `＊OnMouseDoubleClick` | つつかれ反応 |
| `＊OnMouseWheel` | ころころ反応 |
| `＊OnCommunicate` | コミュニケート |
| `＊OnSurfaceRestore` | サーフェス戻し |

エラーは出ない。定義したトークは正常に動くので、
「なでても反応しなくなった」という形でしか気づけない。

これらに反応を足したいなら、イベント名ではなく里々の記法を使う。
`OnMouseMove` ではなく `＊0Headなでられ`、`OnSecondChange` ではなく `＄○○タイマ`。

**日本語のトーク名にも、里々が使っているものがある。**`＊起動` `＊終了` `＊初回`
`＊消滅指示` など、イベントに定義が無いときに里々が探しに来る名前。
別の用途に付けると、意図しない場面で話される。

内蔵処理を作り変えたいとき、なで反応の感度を部位ごとに変えたいとき、
書いたのに動かないときは、`internals.md` の「一部のイベントは里々が処理している」と
「イベント名は日本語のトーク名へ読み替えられる」を読む。

### 自分で作るイベント名を、パスカルケースにしない

選択肢の ID を `On` で始めると、その名前のイベントが直接起きる（[選択肢](#選択肢)）。
`\![raise,イベント名]` も同じ。名前は自由に決められる。

**だが SHIORI のイベントと同じ名前にすると、ベースウェアが
そのイベントを送ってきたときにも反応する。**意図しない場面で喋る。

SHIORI のイベント名はパスカルケース。`On` は残したまま、その直後を崩せば一致しない。

```
On_answer      On選択回答
```

`On` を外すと選択肢の特殊処理に入らず、引数を渡せなくなる。

既にある辞書が `OnAnswer` のような名前を使っていても、直さない。

### 文字列比較に == を使わない

比較対象に演算子の断片（`-` `!` `<` など）が含まれていると、
条件式として解釈されて壊れる。

| 関数 | 大文字小文字 | 半角全角 |
|---|---|---|
| `equal` | 区別する | 区別する |
| `compare_case` | 区別する | 同一視する |
| `compare` | 同一視する | 同一視する |

厳密に比べたいなら `equal`。`compare` は `ABC` と `ａｂｃ` を同じと判定する。

### カッコの対応が壊れると、ファイル全体が無効になる

里々が報告してくれる数少ない誤りだが、影響範囲が大きい。

- **そのファイルは丸ごと読み込まれない。**無関係なトークまで一斉に消える
- 起動は成功する。`load` は通り、エラーは `ErrorLevel` ヘッダと内部ログにしか出ない
- 報告されるのはファイル名まで。行番号は出ない

### 未定義がそのまま表示される

```
（カウター）      タイポ。「（カウター）」という文字列がバルーンに出る
```

変数・トーク・単語群・関数のいずれにも該当しない括弧は、括弧ごと文字として残る。
エラーにならないので、実際に出力を見るまで気づけない。
内部ログでは ` not matched.` として記録される。

同じ見た目になる原因がもう1つある。再帰や多重ループで呼び出しを重ねすぎると、
里々が途中で展開を打ち切る。このときも括弧が文字として残り、報告は出ない。
**名前が合っているのに展開されていないなら、呼び出しの深さを疑う。**

### calc の結果が整数に丸められる

小数点以下を切り捨てる。小数が必要なら `calc_float` を使う。

**数値は 32bit 符号付き整数。**上限は約21億。
秒やミリ秒に直すと、思ったより早く桁があふれる。
`calc_float` では解決しない。桁の問題であって、精度の問題ではない。

### 起動回数は「SHIORI が読み込まれた回数」

ゴーストを起動した回数ではない。ネットワーク更新・辞書フォルダの変更・
辞書の再読み込みでも増える。

```
＞５回目のイベント<TAB>（起動回数）＝＝５        起きないことがある
```

起動を経ずに値が 5 になると、**そのイベントは永久に起きない。**

- `＞＝` で書く。「5回以上」なら取りこぼさない
- 厳密に数えるなら、起動イベントの中で自分で増やす

## 出力の変換

**里々が返すのは、辞書に書いた文字列そのものではない。**
括弧を展開し終えた後、さくらスクリプトとして組み立て直される。
この段階で初めて、さくらスクリプトが意味を持つ（[評価モデル](#評価モデル)）。

### 自動で行われる加工

書いた覚えのないタグが出てきたら、この表のどれか。

| 加工 | 何が入る・変わる | どこ |
|---|---|---|
| 改行 | `＊` の本文の改行が `\n` になる | [定義](#定義) |
| 話者 | `：` ごとに `\0` `\1` が入る | [話者の切り替わり方](#話者の切り替わり方) |
| 先頭 | 応答の先頭に `\0` `\1` とサーフェス指定が入る | [先頭に挿入されるスコープとサーフェス](#先頭に挿入されるスコープとサーフェス) |
| ウェイト | 句読点から `\_w[…]` が入る | [自動で入るウェイト](#自動で入るウェイト) |
| サーフェス | `（５）` が `\s[5]` になる | [括弧](#括弧) |
| 選択肢 | `＿` が `\q[…]` になる。ID も書き換わることがある | `internals.md`「選択肢の ID 書き換え」 |
| 終端 | 末尾の改行が除かれ、`\e` が付く | ─ |
| 置換 | `replace.txt`（評価前）と `replace_after.txt`（評価後） | `internals.md`「置換ファイルのタイミング」 |

`＄` や `＞` で始まる行は、行全体を占有するので改行の対象にならない。

`φ` を置くと、その位置の自動処理が止まる（[自動処理を止める記号 φ](#自動処理を止める記号-φ)）。

### 自動で入るウェイト

**何も設定しなくても、句読点から `\_w[…]` が挿入される。**`replace.txt` は関係ない。

```
：こんにちは、今日はいい天気ですね。
→ こんにちは、\_w[36]今日はいい天気ですね。
```

`＠` から持ってきたセリフにも同じように入る（[定義](#定義)）。

**挿入される値を前提にしない。**台詞の長さと設定で変わり、
設定によっては実行するたびに違う値になる。

値の決まり方と `＄自動挿入ウェイトタイプ` `＄自動挿入ウェイトの倍率` は
`internals.md` の「自動で入るウェイト」にある。

### ウェイトを止める

| 範囲 | 書き方 |
|---|---|
| その位置だけ | `φ` を置く |
| 囲んだ範囲 | `\_q` 〜 `\_q` で囲む |
| 以後すべて | `＄自動挿入ウェイトタイプ<TAB>無効`、または `＄自動挿入ウェイトの倍率<TAB>0` |

```
：あ、い、う、え。      → あ、\_w[12]い、\_w[12]う、\_w[12]え。
：あ、い、うφ、え。     → あ、\_w[12]い、\_w[12]う、え。

：ふつう、です。\_qクイック、です。\_qまたふつう、です。
→ ふつう、\_w[24]です。\_w[18]\_qクイック、です。\_qまたふつう、\_w[36]です。
```

`\_q` の中にだけ挿入されない。里々は出力を組み立てるときに `\_q` を見ている。

これは [評価モデル](#評価モデル) の例外ではない。辞書を評価している間は
さくらスクリプトが1文字も機能しないが、自動挿入はそれが終わった後の段階で行われる。
`\_q` が効くのはその段階。

### 自動処理を止める記号 φ

`φ` は、直後の1つに対する自動処理を止める。`φ` 自体は出力に残らない。

| 止まるもの | 書き方 |
|---|---|
| ウェイトの自動挿入 | `あ、い、うφ、え。` → `う、` の後だけ入らない |
| 改行 | `＠` の行末に置くと次の行と繋がる（[定義](#定義)） |
| `replace_after.txt` の置換 | `うおーφ！！` → 1つ目の `！` だけ置換されない |
| 括弧の展開 | `φ（乱数0～9）` → `（乱数0～9）` と文字で出る |

効くのは直後の1つだけ。続けて止めたいなら、その数だけ置く。

```
：うおー！！          置換の設定があれば両方とも置換される
：うおーφ！φ！       両方とも置換されない
```

括弧は開くほうに付ければよい。`φ（…）` で閉じ側は要らない。

### 壊れるのは第2段階

組み上がった文字列に半角 `,` `[` `]` `\` が紛れ込むと、
ベースウェアがタグの区切りを誤認する。
**外部由来の文字列をタグの引数に埋めるときは、半角記号を全角へ置換するなどの手当てが要る。**

### よく使うタグ

| タグ | 用途 |
|---|---|
| `\0` `\1` | スコープ切り替え（本体／相方） |
| `\s[N]` | サーフェス変更 |
| `\n` `\n[half]` | 改行 |
| `\_w[ミリ秒]` `\w1`〜`\w9` | ウェイト |
| `\e` | スクリプト終端 |
| `\q[表示文字,ID]` | 選択肢 |
| `\_q` 〜 `\_q` | 囲んだ範囲のクイックセクション（ウェイトを無視） |
| `\![raise,イベント名,…]` | 自分に別のイベントを発生させる |
| `\![embed,…]` | 別のスクリプトを埋め込む |
| `\_u[0xXXXX]` | Unicode 文字を直接指定 |
| `\f[…]` | フォント・色の指定 |

`\![raise]` `\![embed]` は次のイベントを呼ぶ。
ベースウェアがこれらを解釈すると、SHIORI へ新たなリクエストが飛ぶ。

### さくらスクリプトは大文字と小文字を区別する

同じ字でも、大文字と小文字は別のタグである。対になっていることが多く、
関連はするが、動作は違う。

```
\c              現スコープのバルーンの中身をクリアする
\C              先頭に置くと直前のバルーンに追記する。バルーンを閉じない
                スコープは 0番（\0）に戻る

\_v[ファイル名]  音を再生する
\_V              \_v の再生が終わるのを待つ
```

取り違えてもエラーにならない。意図と違う動作のまま動き続ける。
一覧には `\c` も `\C` も並ぶ。
**対になるタグが無いことを確かめてから使う。**

`\C` には、先頭に置けるかどうかと、いつ表示されるかの制約がある。
書き方は `display.md`、実行中に割り込ませたときの挙動は
`capabilities.md`「実行の途中には手を出せない」。

### さくらスクリプトの寿命

既定はそのスクリプト1回（`\e` まで）。
「ゴースト終了まで有効」は、説明に明記された例外だけ。

専用画面を組むタグはこの例外に当たる。`\![set,sticky-window]` `\![set,zorder]`
`\![set,alignmenttodesktop]` は、解除するまで残る（→ `ui_architecture.md`）。

## 書き方は1つではない

同じことを書く方法が複数ある。どれも動く。

| やること | 行頭記号で書く | 関数で書く |
|---|---|---|
| 分岐 | `＞ジャンプ先<TAB>条件` | `（when,条件,真,偽）` |
| 繰り返し | `＞` によるジャンプ | `（loop,…）` `（times,…）` `（for,…）` `（while,…）` |
| 代入 | `＄名前<TAB>値` | `（set,名前,値）` |
| 選択肢 | `＿選択肢名<TAB>行き先` | `\q[表示,ID]` を直接書く |

関数をまったく使わない辞書がある。`＞` `＄` `＿` だけで最後まで書かれている。
それで不足があるわけではない。

**既存の辞書に手を入れるなら、そこで使われている書き方に合わせる。**
読む人が規約を掴めなくなるのを避けるためで、どちらかが正しいからではない。

関数の追加時期には差がある（`times` `for` `while` は `loop` より後、
`equal` や `vncall` はさらに後）。
古い辞書にそれらが出てこないのは、書いた時点で無かったというだけ。
手を入れるときに使ってはいけない理由にはならない。
