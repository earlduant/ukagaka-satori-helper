# 里々が黙ってやっていること

辞書を読んでも分からない挙動を集めた。里々が dll の中で肩代わりしている処理で、
書いた覚えのないものが動いたり、書いたのに動かなかったりする原因になる。

通読する必要はない。次のようなときに引く。

- なで反応・つつかれ反応を作り込みたい、内蔵の挙動を変えたい
- 書いた覚えのない動きをする、または書いたのに動かない
- `＊OnMouseMove` のようにイベント名をそのままトーク名にしようとしている

記法そのものは `syntax.md`、確かめ方は `testing.md`。

## 一部のイベントは里々が処理している

里々は、辞書に何も書かなくても一部のイベントに応答する。
なで反応もランダムトークもタイマも、里々が内蔵している機能で実現されている。

**同じ名前のトークを定義すると、その内蔵処理が止まる。**

| イベント名 | 定義すると止まるもの |
|---|---|
| `OnSecondChange` | **ランダムトークと `＄○○タイマ` の両方** |
| `OnMouseMove` | なでられ反応（`＊0Headなでられ` など） |
| `OnMouseDoubleClick` | つつかれ反応（`＊0Headつつかれ` など） |
| `OnMouseWheel` | ころころ反応（`＊0Headころころ` など） |
| `OnCommunicate` | 話しかけられたときの応答（[下記](#oncommunicate-の処理)） |
| `OnSurfaceRestore` | サーフェス戻し |

エラーは出ない。定義したトーク自体は正常に動くので、
「なでても反応しなくなった」という形でしか気づけない。

止まるのは定義したイベントの担当ぶんだけ。`＊OnMouseMove` を書いても、
つつかれ・ころころ・ランダムトーク・タイマは動き続ける。

### 例外1 ── トークを出力しない `＊OnSecondChange` は無害

`＊OnSecondChange` を定義しても、トークを出力しなければ内蔵処理は止まらない。

```
＊OnSecondChange
＄経過カウンタ＝（経過カウンタ）＋１
（nop,（set,秒数記録,（現在秒）））
```

これならランダムトークもタイマも動き続ける。
秒ごとに何かを数えたいだけなら、この形で書く。

`：` でセリフを書いた時点で止まる。

### 例外2 ── ホールドは `OnMouseDown` / `OnMouseUp` を書いても動く

`＊0Headホールド` は `OnMouseDown` → `OnSecondChange` → `OnMouseUp` の組で実現されているが、
このうち `OnMouseDown` と `OnMouseUp` は、トークを書いても内蔵処理が止まらない。

ただし `OnSecondChange` を止めれば、ホールドも止まる。

### 自分で定義したときの挙動

`OnSurfaceRestore` で確かめた例。内蔵処理の出力が消えて、書いたトークに置き換わるのではない。

```
（＊OnSurfaceRestore を定義しない）
→ \1\s[10]\e                          里々が組み立てた応答だけが返る

＊OnSurfaceRestore
：自分で書いた応答
→ \0\s[7]\1\s[10]\0自分で書いた応答\e   先頭の自動挿入は残る
```

普通の `＊` として処理されるようになるだけで、
先頭のサーフェス挿入（`syntax.md` の「先頭に挿入されるスコープとサーフェス」）は
そのまま働く。

## イベント名は日本語のトーク名へ読み替えられる

一部のイベントには、里々が内蔵している日本語のトーク名がある。
`＊OnBoot` が無ければ `＊起動` が探される。`＞起動` と書く必要はない。

上から順に探し、最初に見つかったものが使われる。

| イベント | 探す順 |
|---|---|
| `OnBoot` | `＊OnBoot` → `＊起動` |
| `OnClose` | `＊OnClose` → `＊終了` |
| `OnFirstBoot` | `＊OnFirstBoot` → `＊初回` → `＊OnBoot` → `＊起動` |
| `OnGhostChanged` | `＊OnGhostChanged` → `＊他のゴーストから変更` → `＊OnBoot` → `＊起動` |
| `OnGhostChanging` | `＊OnGhostChanging` → `＊他のゴーストへ変更` → `＊OnClose` → `＊終了` |
| `OnVanishSelecting` | `＊OnVanishSelecting` → `＊消滅指示` |
| `OnVanishCancel` | `＊OnVanishCancel` → `＊消滅撤回` |
| `OnVanishSelected` | `＊OnVanishSelected` → `＊消滅決定` |
| `OnVanishButtonHold` | `＊OnVanishButtonHold` → `＊消滅中断` |
| `OnSecondChange` | `＊OnTalk`（`＄喋り間隔` に達した秒だけ） → `＊`（名前なし＝ランダムトーク） |

初回・交代は、専用のトークが無ければ通常の起動・終了へ落ちる。
`＊OnFirstBoot` も `＊初回` も無いゴーストで初回起動すると、`＊起動` が話される。

**この名前は他の用途に使えない。**`＊終了` という名前で
「何かの処理の終わり」を書くと、ゴーストの終了時に話される。

古い辞書にある `＊OnBoot` ＋ `＞起動` という書き方は、この読み替えと同じ結果になる。
条件で行き先を分けたいときだけ、`＞` で明示的に飛ばす。

```
＊OnBoot
＞誕生日	（現在月）（現在日）＝＝（誕生日）
＞起動
```

## ＊OnTalk ── ランダムトークの前に呼ばれる

定義は省略できる。無ければ `＊`（名前なし）が直接話される。

書くなら、次の形に追加する。

```
＊OnTalk
＞（Ｒ１）	（Ｒ０）
（）
```

| | |
|---|---|
| `＞（Ｒ１）	（Ｒ０）` | 予約があるときだけ、そのトークへ飛ばす |
| `（）` | 名前のないトークを呼ぶ。ランダムトーク本体 |

**1行目を消すと、トークの予約が動かなくなる。**
既にある `＊OnTalk` に処理を足すときは、この2行を残す。

### `（Ｒ０）` `（Ｒ１）` は里々が埋める

SSP から来る値ではない。テスターで Reference を送っても無視される。

| 状態 | `（Ｒ０）` | `（Ｒ１）` |
|---|---|---|
| 通常 | `0` | 空 |
| 予約済み | `1` | 予約されたトーク名 |

### トークを予約する

```
＄次のトーク	トーク名             次のランダムトークで呼ばれる
＄次から３回目のトーク	トーク名    3回あとのランダムトークで呼ばれる
```

予約したトーク名と同じ名前のトークが複数あれば、そのうち1つがランダムに選ばれる。

**予約名に裸の数字を使わない**
（→ `syntax.md` の「変数・単語群・トークは名前空間を共有する」）。

## 里々独自の起動・終了イベント

SSP が送るイベントとは別に、里々が自分で呼ぶものが4つある。

| | |
|---|---|
| `OnSatoriLoad` | 辞書を読み込んだ後 |
| `OnSatoriBoot` | 起動処理の前 |
| `OnSatoriClose` | 終了・交替の前 |
| `OnSatoriUnload` | 終了処理の最後。**トークを返しても使われない** |

### 終了時に確実に通るのは OnSatoriClose

終了の経路は4つあるが、どれも `OnSatoriClose` を通る。

```
\- で終了      OnSatoriClose → OnClose
SSP ごと終了   OnCloseAll → OnSatoriClose → OnClose
ゴーストのみ   OnSatoriClose → OnClose
交替           OnSatoriClose → OnGhostChanging
```

終了時に値を保存するなら、ここに書く。

```
＊OnSatoriClose
＄終了時刻	（現在通算秒）
```

## 内蔵処理を作り変える

内蔵処理と同じ動きをする里々スクリプトを辞書に書けば、
再現したうえで好きに改造できる。

以下はテスターで内蔵処理と同じ結果になることを確認したもの。

### なでられ ── OnMouseMove

```
＊OnMouseMove
＄計算用なでられ回数＝（計算用なでられ回数）＋１
＄なでられ回数初期化タイマ＝（なでられ持続秒数）
＞なにもしない	（count、（Status）、talking）＞０＆＆（トーク中のなでられ反応）＝＝無効
＞なにもしない	（計算用なでられ回数）＜（なでられ反応回数）
＄計算用なでられ回数＝０
＞（R3）（R4）なでられ

＊なにもしない

＊なでられ回数初期化
＄計算用なでられ回数＝０
```

- `（R3）` がスコープID（本体なら 0）、`（R4）` が当たり判定名。
  つないで `＞0Headなでられ` というジャンプ先を組み立てている
- `＄なでられ反応回数` の回数ぶん `OnMouseMove` を受けて、はじめて1回反応する。既定は 60
- `＄なでられ持続秒数` の間なでられないと、カウントがリセットされる（既定 2）

部位ごとに感度を変えるなら、カウンタを部位ごとに分ける。

```
＊OnMouseMove
＄なでられ回数初期化タイマ＝（なでられ持続秒数）
＞なにもしない	（count、（Status）、talking）＞０＆＆（トーク中のなでられ反応）＝＝無効
＄計算用Headなでられ回数＝（計算用Headなでられ回数）（when、（R4）＝＝Head、＋１）
＞なにもしない	（計算用Headなでられ回数）＜50＆＆（R4）＝＝Head
＄計算用なでられ回数＝（計算用なでられ回数）（when、（R4）！＝Head、＋１）
＞なにもしない	（計算用なでられ回数）＜60＆＆（R4）！＝Head
＄ダミー	（なでられ回数初期化）
＞（R3）（R4）なでられ

＊なにもしない

＊なでられ回数初期化
＄計算用なでられ回数＝０
＄計算用Headなでられ回数＝０
```

`（when、（R4）＝＝Head、＋１）` は、条件に合うときだけ `＋１` という文字列を返す。
返らなければ `＄計算用Headなでられ回数＝（計算用Headなでられ回数）` となり、値が変わらない。

`＄ダミー	（なでられ回数初期化）` は、呼び出しの結果で改行が入るのを避けるために
変数へ捨てている。

### つつかれ ── OnMouseDoubleClick

```
＊OnMouseDoubleClick
＞（R3）（R4）つつかれ
（）
```

ジャンプ先が無ければ次の行へ進むので、`＊0Headつつかれ` が未定義なら
`（）`（ランダムトーク）が出る。つつかれトークを書いていない部位をつついても
黙り込まない、という作りになっている。

### ころころ ── OnMouseWheel

```
＊OnMouseWheel
＄計算用マウスホイール＝（when、（計算用マウスホイール）＞＝２、１、（計算用マウスホイール）＋１）
＄計算用マウスホイール初期化タイマ＝２
＞（R3）（R4）ころころ	（計算用マウスホイール）＞＝２

＊計算用マウスホイール初期化
＄計算用マウスホイール＝０
```

2回転ごとに1回反応する。カウンタは 2 に達すると 1 へ戻る。

トーク中に反応させたくないなら、条件を足す。

```
＞（R3）（R4）ころころ	（計算用マウスホイール）＞＝２＆＆（count、（Status）、talking）＝＝０
```

### サーフェス戻し ── OnSurfaceRestore

```
＊OnSurfaceRestore
：（（デフォルトサーフェス0））
：（（デフォルトサーフェス1））
```

`（（デフォルトサーフェス0））` は二重の括弧。内側が変数の値（例：`5`）に展開され、
外側の `（5）` がサーフェス指定 `\s[5]` になる
（`syntax.md` の「評価モデル」）。

挿入される値の決まり方は[サーフェスの自動挿入](#サーフェスの自動挿入)。

## 再現スクリプトを使う前に

上のスクリプトは、そのまま貼っても期待どおり動かないことがある。
読んでいる変数に前提がある。

### 特殊変数は、代入するまで読めない

`＄なでられ反応回数` などは書き込み用の特殊変数で、
里々が内部に持っている既定値を `（なでられ反応回数）` で読むことはできない。

```
（何も代入していない状態）
：（なでられ反応回数）     → 「（なでられ反応回数）」と表示される

＄なでられ反応回数	3
：（なでられ反応回数）     → 3
```

**未設定のまま再現スクリプトを動かすと、条件式が壊れる。**
`（計算用なでられ回数）＜（なでられ反応回数）` の右辺が文字列のままになり、
数値として読めないので 0 と扱われる（`syntax.md` の「真偽の決まり方」）。
結果、1回なでるたびに反応する。

再現スクリプトを使うなら、起動時のイベントで値を明示的に代入しておく。

```
＊OnSatoriBoot
＄なでられ反応回数	60
＄なでられ持続秒数	2
＄トーク中のなでられ反応	無効
```

代入した値は、内蔵処理と再現スクリプトの両方が同じように使う。

### `（Status）` はテスターでは取れない

`（count、（Status）、talking）` は「いま喋っている最中か」を見ている。
`（Status）` はベースウェアが送ってくる値なので、
テスターでは展開されず、文字列のまま残る。

テスターで動かすと `count` が 0 を返し、この条件は常に偽になる。

**トーク中の抑制が効いているかは、SSP で動かさないと分からない。**
テスターの結果だけを見て「この行は要らない」と判断しない。

## 自動で入るウェイト

句読点などから `\_w[…]` が自動で挿入される。`replace.txt` の設定とは関係なく入る。

| 変数 | 値 | 動き |
|---|---|---|
| `＄自動挿入ウェイトタイプ` | `里々` | 既定。台詞が長いほどウェイトも長くなる |
| | `一般` | 里々より大幅に長い。**実行のたびに値が変わる** |
| | `無効` | 一切挿入されない |
| `＄自動挿入ウェイトの倍率` | `100` | 既定。パーセントで指定する |
| | `0` | 挿入されない |
| | `50` `200` | 挿入される値がそのまま比例する |

同じ1文で測った結果。**この数値そのものを当てにしない。**

| 設定 | 「、」の後 | 「。」の後 |
|---|---|---|
| 既定（`里々` / 100） | `\_w[36]` | `\_w[66]` |
| 倍率 `50` | `\_w[18]` | `\_w[33]` |
| 倍率 `200` | `\_w[72]` | `\_w[132]` |
| タイプ `一般`（1回目） | `\_w[226]` | `\_w[306]` |
| タイプ `一般`（2回目） | `\_w[154]` | `\_w[316]` |

倍率は挿入される値に正確に比例する。

`一般` はランダムに揺れる。同じ辞書・同じ入力でも実行ごとに違う値が入る。
出力を比較するテストを書くなら `里々` か `無効` にする。

`里々` でも台詞の長さで変わる。短い文では、同じ「、」が `\_w[24]` になった。
長さと値の対応は公開されていない。特定の数値を前提にした辞書を書かない。

止め方は `syntax.md` の「ウェイトを止める」。

## 選択肢の ID 書き換え

**里々はトーク中の `\q[…]` の ID を書き換える。**
`＿` から作ったものだけでなく、自分で書いた `\q` も対象。
ただし ID の中身によっては手を付けない。

| ID | 書き換え |
|---|---|
| ふつうの文字列（`ジャンプ先` など） | される |
| `On` で始まる | されない |
| `script:` で始まる | されない |
| `\__q[…]` の ID | されない（この形式は対象外） |

```
＿えらぶ                 → \q[えらぶ,えらぶ◆えらぶ◆1]
＿えらぶ<TAB>ジャンプ先   → \q[えらぶ,ジャンプ先◆えらぶ◆1]
\q[えらぶ,ID1]           → \q[えらぶ,ID1◆えらぶ◆1]

＿test<TAB>On_ID         → \q[test,On_ID]               そのまま
\q[test,On_ID]           → \q[test,On_ID]               そのまま
\q[test,On_ID,r0,r1]     → \q[test,On_ID,r0,r1]         そのまま
\q[test,script:\e]       → \q[test,script:\e]           そのまま
\__q[On_ID,param]…\__q   → そのまま

◆ は 0x01
```

書き換えるときは、元の ID の後ろにラベルと番号を足す。番号は 1 から数える。

選択肢が選ばれて `OnChoiceSelect` が返ってくると、里々はこの ID を分解し、
`（選択ＩＤ）（選択ラベル）（選択番号）` に入れてから、
`（Ｒ０）` には ID だけを入れ直す。
選択肢の情報取得変数を実装するために、この書き換えをしている。

### なぜ `On` と `script:` を避けるのか

どちらも SSP 側で特別な意味を持つ。

- `On` で始まる ID は、選択時にその名前の SHIORI イベントが直接発生する
- `script:` で始まる ID は、その内容がさくらスクリプトとして実行される

書き換えれば `On_ID◆ラベル◆1` という名前のイベントを要求することになり、
壊れる。里々はそれを避けている。

### 書き換えられなければ選択肢変数も更新されない

`OnChoiceSelect` で戻ってきても、分解する対象が無いため。

**更新されないとき、変数は空にならない。前に選んだ値がそのまま残る。**
書き換えられる選択肢と `On` 始まりの選択肢を混ぜて使うと、
`On` のほうを選んだのに前回の値が返る。

`On` や `script:`、`\__q` を使うなら、選択肢変数に頼らない。

### OnChoiceSelect は定義しなくても動く

`＊OnChoiceSelect` を書かなくても、里々が処理する。

1. ID を 0x01 で分解し、`（選択ＩＤ）（選択ラベル）（選択番号）` にセット
2. `（Ｒ０）` を ID だけに置き換え
3. その ID と同じ名前のトークへジャンプ

`＿えらぶ<TAB>ジャンプ先` と書くだけで `＊ジャンプ先` が呼ばれるのは、3のため。

`＊OnChoiceSelect` を定義しても、1と2は行われる。
分解済みの値を受け取ったうえで、処理を足せる。

### OnChoiceSelectEx には手を付けない

SSP は `OnChoiceSelect` より先に `OnChoiceSelectEx` を送る。
里々はこれに何もしない。定義しなければ 204 を返すだけ。

| | `（Ｒ０）` | `（Ｒ１）` | `（Ｒ２）`以降 |
|---|---|---|---|
| `OnChoiceSelect` | ID | ─ | ─ |
| `OnChoiceSelectEx` | ラベル | ID | `\q` の3番目以降の引数 |

並びが逆。

`＊OnChoiceSelectEx` で `＞（Ｒ１）` と書いてジャンプさせる手があるが、
**`\q` で出した選択肢では ID が加工済みなので飛べない。**

```
\q[test,ID1,param1,param2]
→ \q[test,ID1◆test◆1,param1,param2]      ID だけ加工され、引数は残る

（Ｒ１） ＝ ID1◆test◆1                    この名前のトークは無い
```

`\__q` なら加工されない。引数つきで `OnChoiceSelectEx` を使うならこちら。

```
\__q[ID1,param1,param2]test\__q     そのまま渡る

＊OnChoiceSelectEx
＞（Ｒ１）

＊ID1
：引数1は（Ｒ２）、引数2は（Ｒ３）
```

書き換えられた ID は応答にそのまま現れる。
`replace_after.txt` と `OnTranslate` が受け取るのも、書き換えた後の文字列。

**トーク全文を関数へ渡すとき、引数区切りに 0x01 を使えない**のはこのため
（`syntax.md` の「引数区切りの誤爆」）。
選択肢を含むトークには、必ず 0x01 が混ざっている。

## サーフェスの自動挿入

里々は、辞書に書かなくてもサーフェス指定を挿入する。
これは `＄会話時サーフェス戻し` が有効なとき（既定）の挙動。

挿入されるのは2つのタイミングで、個別に切り分けることはできない。

| | いつ |
|---|---|
| トークの先頭 | そのイベントで最初に選ばれた `＊` の応答の先頭 |
| トークの後 | `OnSurfaceRestore` を受けたとき |

この節は、以下すべて有効のときの話。止め方は[止める](#止める)。

### 挿入される値

`＄デフォルトサーフェス0` `＄デフォルトサーフェス1` の値がそのまま入る。

| 設定 | 挿入されるもの |
|---|---|
| 何も設定しない | `\1\s[10]` |
| `＄デフォルトサーフェス0<TAB>0` | `\0\s[0]\1\s[10]` |
| `＄デフォルトサーフェス0<TAB>5` | `\0\s[5]\1\s[10]` |
| `＄デフォルトサーフェス1<TAB>25` | `\1\s[25]` |

- **`＄デフォルトサーフェス0` は、未設定と `0` が違う。**
  未設定なら `\0\s[…]` は挿入されず、`0` を入れれば `\0\s[0]` が挿入される
- `＄デフォルトサーフェス1` の既定は `10`

トークの先頭でサーフェスを指定していれば、`\0` 側は挿入されない。
`＄デフォルトサーフェス0` を設定していても、先頭の指定が優先される。

### `＄サーフェス加算値` は加算されない

**`＄サーフェス加算値0` を設定すると、`＄デフォルトサーフェス0` が同じ値に上書きされる。**

```
＄サーフェス加算値0	100                      → \0\s[100]\1\s[10]

＄サーフェス加算値0	100
＄デフォルトサーフェス0	5                    → \0\s[5]\1\s[10]

＄デフォルトサーフェス0	5
＄サーフェス加算値0	100                      → \0\s[100]\1\s[10]
```

後に書いたほうが残るだけで、5 と 100 が 105 になることはない。
`＄サーフェス加算値0` が効くのは本文中のサーフェス指定に対してで、
自動挿入される値には足されない。

両方使うなら `＄サーフェス加算値0` を先に書き、
`＄デフォルトサーフェス0` には加算後を見越した値を入れる。

### 時間が経つと戻る ── OnSurfaceRestore

SSP が喋りタイムアウトの秒数 + 15秒後に一度送る。
**このイベントは、辞書に書かなくても里々が応答する。**

```
[OnSurfaceRestore]   → 200 OK  \1\s[10]\e     定義が無くても返る
[OnMouseMove]        → 204 No Content          他の未定義イベントは応答しない
```

返る中身は先頭挿入と同じ。

```
＄デフォルトサーフェス0	7 を設定済み
[OnSurfaceRestore]   → \0\s[7]\1\s[10]\e
```

`＊OnSurfaceRestore` を自分で定義すると、自動挿入の後ろに本文が続く。

```
＊OnSurfaceRestore
：自分で書いた応答

→ \0\s[7]\1\s[10]\0自分で書いた応答\e
```

辞書に何も書いていないのに、しばらくすると表情が戻るのはこれ。
辞書を探しても原因が見つからない。

### 止める

| 変数 | 値 | 効果 |
|---|---|---|
| `＄会話時サーフェス戻し` | `無効` | 以後ずっと止まる。先頭の `\1\s[…]` も、`OnSurfaceRestore` も |
| `＄今回は会話時サーフェス戻し` | `無効` | そのトークの先頭だけ。次のトークでは戻る |

```
＄会話時サーフェス戻し	無効
：あ                        → \0あ      次のトークも \0あ のまま

＄今回は会話時サーフェス戻し	無効
：あ                        → \0あ      次のトークは \1\s[10]\0あ に戻る
```

`＄会話時サーフェス戻し<TAB>無効` にすると、`OnSurfaceRestore` は 204 を返す。
`＄今回は会話時サーフェス戻し` はそのトーク1回きりなので、
`OnSurfaceRestore` には効かない。

## OnCommunicate の処理

話しかけられたときに来る SHIORI イベントが `OnCommunicate`。
コミュニケートボックス（`\![open,communicatebox]` で開く）への入力と、
他ゴーストからの発話が、どちらもこれで届く。

| | 中身 |
|---|---|
| `（Ｒ０）` | ボックスからなら `user`、ゴーストからはそのゴーストの本体側の名前 |
| `（Ｒ１）` | 発言の内容 |

里々はこのイベントを内蔵処理している。中身はこうなっている。

```
＊OnCommunicate
≫ユーザ「　（Ｒ１）	（compare,（Ｒ０）,user）
≫（Ｒ０）「　（Ｒ１）
≫「　（Ｒ１）
＞COMMUNICATE該当なし
```

`＊ユーザ「　○○` という独特なトーク名は、この処理が決めている。
里々の記法ではなく、内蔵処理が探しに来る名前。

| 書くトーク | 拾われるとき |
|---|---|
| `＊ユーザ「　○○` | コミュニケートボックスからの入力 |
| `＊<ゴースト名>「　○○` | そのゴーストから話しかけられた |
| `＊「　○○` | 上のどちらでも拾えなかったとき |
| `＊COMMUNICATE該当なし` | どれにも当たらなかったとき |

`＊OnCommunicate` を定義すると、この4つは**一切呼ばれなくなる。**

### 一致率の計算

`≫`（`syntax.md` の「行頭記号」）は完全一致では探さない。
候補それぞれに点を付け、最も高いものへジャンプする。同点ならランダムに選ぶ。

トーク名は `「　` で前後に分かれる。

```
＊ユーザ「　ケーキ　アイス
      ~~~~     ~~~~~~~~~~~~
      前半      後半＝候補の単語（全角スペース区切り）
```

前半は候補を絞る。`＊ユーザ「　…` は `≫ユーザ「　…` からしか拾われない。
後半の単語を、渡された文字列と突き合わせて点を出す。

既定は次の式。

| | 点 |
|---|---|
| 単語が1つ一致 | ＋10 |
| 一致した単語の長さ（半角換算） | ÷4 して加点 |
| 一致しなかった単語1つにつき | −1 |

5点以上の候補が無ければ、ジャンプせず次の行へ進む。
里々の内蔵処理では、このとき `＊COMMUNICATE該当なし` が呼ばれる。

**候補を並べるほど不利になる。**表記ゆれを吸収しようとして単語を増やすと、
一致しなかったぶんが引かれて基準を割る。

```
＊試験「　かわいい　可愛い　きれい　綺麗　うつくしい　美しい　すてき　素敵　可憐

≫試験「　かわいい
```

「かわいい」は一致するが、ジャンプしない。
一致 10 ＋ 長さ 8÷4 ＝ 2 − 不一致 8語 ＝ 4点で、5点に届かない。

### 切り替える ── `＄コミュニケートの検索方法`

```
＄コミュニケートの検索方法	合計文字数
```

| 値 | 計算 |
|---|---|
| `里々` | 既定。上の方式 |
| `合計文字数` | 一致した単語の長さ（半角換算）× 10 だけで決まる |

`合計文字数` では不一致のペナルティが無い。上と同じ辞書・同じ入力で
8×10 ＝ 80点となり、ジャンプする。

表記ゆれを大量に並べるなら `合計文字数` にする。
`里々` のままだと、候補を足すほど反応しなくなる。

変数名は「コミュニケートの」だが、
`OnCommunicate` の内蔵処理に限らず、自分で書いた `≫` にも効く。

### 組み合わせた条件は書けない

`≫` が見るのは、単語が含まれるかどうかだけ。語順は問わない。
「かわいいね」でも「すごくかわいい」でも拾える。

```
＊ユーザーからの反応「　かわいい
：ありがとう！

≫ユーザーからの反応「　（Ｒ１）
```

**「犬と猫の両方が含まれていたら」は書けない。**
点の合計で1つに決まる仕組みなので、条件を掛け合わせられない。

揃ったときだけ分けたいなら、`count` で自分で組む。

```
（when，（count,（Ｒ１）,犬） ＆＆ （count,（Ｒ１）,猫），（両方いるときのセリフ））
```

## 置換ファイルのタイミング

`replace.txt` と `replace_after.txt` は、上から順に機械的な文字列置換を行う。
働く時点が違うので、同じ置換を書いても結果が変わる。

| | いつ |
|---|---|
| `replace.txt` | 辞書を読み込むとき。括弧を展開する前 |
| `replace_after.txt` | SSP へ返す直前。括弧を展開した後 |

```
replace.txt         マーク	（乱数0～9）
replace_after.txt   シンボル	（乱数0～9）

：マーク      → 9              置換された後に展開される
：シンボル    → （乱数0～9）    展開が終わった後なので、文字のまま残る
```

`replace.txt` は辞書のマクロとして使える。
里々が括弧を解釈する前に置き換わるので、自分用の短い書き方を作れる。

```
replace.txt
（ステータス確認、	（call、ステータス計算処理、

辞書
（ステータス確認、ＨＰ、１）
→ （call、ステータス計算処理、ＨＰ、１）として読まれる
```

括弧の途中で切った断片も置換できる。置き換わるのは、構文として読まれる前だから。
頻出する長い呼び出しを短くできる。

`replace_after.txt` で書いたものは、もう展開されない。
自動ウェイトの挿入も終わった後なので、置換結果に `、` を混ぜてもウェイトは入らない。

**置換は上から順に連鎖する。**前の行が作った文字列に、次の行が当たる。

```
replace_after.txt
！	！\w9
！\w9！\w9	！！\w9\w5
```

すべての `！` が `！\w9` になり、`！！` だったところは `！\w9！\w9` になる。
それを次の行が `！！\w9\w5` に置き換える。

`replace.txt` は辞書の全文に適用される。辞書が大きく、置換の記述も多いと、
起動が遅くなる。

### 条件で置換を変えたいなら OnTranslate

`replace_after.txt` は固定の対応表しか書けない。
条件によって置換先を変えたいなら [OnTranslate](#ontranslate-の処理) を使う。
働く位置はほぼ同じ。

## OnTranslate の処理

里々が返したスクリプトが、そのまま `（Ｒ０）` として戻ってくるイベント。
SSP は喋る前に必ずこれを送る。SSTP も通る。

| | 中身 |
|---|---|
| `（Ｒ０）` | 組み上がったスクリプト全文。さくらスクリプトに変換済み |

ここで加工したものが、最終的に画面へ出る。
`replace_after.txt` でできることは、だいたいここでもできる。
条件によって置換を変えたいときに使う。

```
＊OnTranslate
＄引数区切り追加	（バイト値,2）
＄出力	（Ｒ０）
＄出力	（replace（バイト値,2）（出力）（バイト値,2）あなたさん（バイト値,2）あなた）
（出力）
```

### このイベントの応答には replace_after が効かない

同じ `replace_after.txt`（`さんさん` → `さん`）を置いて比べた結果。

| | 出力 |
|---|---|
| 通常のトーク `：ユーザさんさん` | `ユーザさん` 置換される |
| `＊OnTranslate` の応答 | `テストさんさん` 置換されない |

二重に置換されることはないので、`replace_after.txt` と併用してよい。
ただしここで書いた加工は `replace_after.txt` に拾われないので、
同じ置換を両方に書いても片方しか働かない。

### φ の保護が外れている

これが最大の落とし穴。

里々は外部から来た文字列を変数へ入れるとき、括弧を `φ（` の形で保護する
（`syntax.md` の「外部から来た文字列は、関数に渡した時点で展開される」）。
**だが出力するとき `φ` は消える。**
SSP が送り返してくる `（Ｒ０）` には、保護が付いていない。

```
Reference0 ＝ あ（０）い

：（Ｒ０）                      → あ（０）い      そのまま出せば無事
：（replace,（Ｒ０）,zz,YY）    → あ\s[0]い      関数に渡すと展開される
```

`（０）` がサーフェス指定として解釈された。
ユーザーが入力した文字列やファイル名が画面に出ているだけなら害はないが、
加工しようとした瞬間にサーフェスが変わる。

`＄変数<TAB>（Ｒ０）` で受ければ保護されるが、関数に渡した時点で外れる。
置換をかけるなら、**先に全角括弧を半角へ潰す。**

### 区切り文字に何を使うか

トーク全文を関数へ渡すので、中に何が入っていてもおかしくない。

- `,` `、` は使えない。セリフに出てくる
- 0x01 も使えない。選択肢を含むトークには必ず混ざっている
  （[選択肢の ID 書き換え](#選択肢の-id-書き換え)）

`＄引数区切り追加` で、トークに出てこない文字を一時的に登録する。
