# 専用画面のアーキテクチャ

通常の会話とは違う画面（ミニゲーム、ステータス画面、特殊メニュー）を作るとき、
表示を置ける場所は2つしかない。

どちらを選ぶかで、用意するもの・崩れ方・確かめられる範囲が変わる。
ここにあるのは、その選択のための材料と、組み合わせないと成立しない型である。

**型は、そのまま当てはめるものではない。**
依頼を要素に分け、必要な部分だけを取り出す。

```
「掴んで並べ替える」から重なりの部分を外すと、クリックで動かす仕組みになる
「時間で動かす」から動きを外すと、間を置いて起きるだけのものになる
```

丸ごと持ってくると、要らない仕組みまで抱え込む。
どの型にも、分けられる境目がある。それぞれの節の冒頭に書いてある。

ここにある3つが全部ではない。分けて、組み直せば、書かれていないものも作れる。

バルーンに描くタグは `display.md`、里々の内蔵挙動は `internals.md`。
`surfaces.txt` `descript.txt` の記法は**仕様を引いて書く。**

## 2つの類型

| | バルーンに出す | シェルに出す |
|---|---|---|
| 表示するもの | 文字と画像 | サーフェスの画像 |
| 位置の決め方 | 文字送りのカーソルを動かす | `surfaces.txt` の座標 |
| 操作の受け方 | 選択肢 → ID と同じ名前のトーク（`On` で始まる ID ならそのイベント。`＊OnChoiceSelect` は書かない） | 当たり判定 → `OnMouseDoubleClick` |
| 用意するもの | 辞書と画像素材 | 画像素材と `surfaces.txt` |
| 見え方 | 利用者のフォントとバルーンの大きさで変わる | ピクセルで決まる。崩れない |

## バルーンに出す

文字を並べて形を作る。枠も、表も、メニューも、バーも、すべて文字で組む。

| | |
|---|---|
| 向く | 一覧、メニュー、数値の表示、テキストで進むもの |
| 向かない | 位置が正確に決まっていないと成立しないもの |

辞書だけで閉じる。画像素材が要らず、書いたものをそのまま確かめられる。

崩れる原因は利用者の側にある。フォントもバルーンの大きさも、ゴーストの作者は決められない。
桁を揃えた表は、別のバルーンでは崩れる。

選択肢を表示している間は `OnSurfaceRestore` が送られないので、選択肢で待つ画面がサーフェス戻しで消えることはない（→ `internals.md`「時間が経つと戻る」）。

書き方は `display.md`。複数のデータを並べるなら `patterns.md`。

## シェルに出す

専用のサーフェスを用意し、当たり判定を置いて、つついた場所で分岐する。

| | |
|---|---|
| 向く | 盤面、ボタン、絵として成立させたいもの |
| 向かない | 文字。サーフェスに文字は出せない |

### 組み立て

```
surfaces.txt   専用のサーフェスと、当たり判定（collision）を定義する
               辞書から動かすものは animation*.interval,never にしておく
辞書           \s[ID]  サーフェスを切り替える
               \i[ID]  定義済みのアニメーションを呼ぶ
               つついた部位で分岐する（OnMouseDoubleClick）
```

**`never` は自動では再生されない**。辞書から呼ぶものをこれにしておかないと、
SSP が独自のタイミングで動かす。

着せ替えも表示の切り替えに使える。`descript.txt` の `bindgroup` に定義すれば
`\![bind,…]` で着脱でき、`menuitem` に載せなければ利用者の着せ替えメニューには並ばない。
見せる着せ替えと、機能のための着せ替えを分けられる。

見た目は崩れない。代わりに3つのコストがかかる。

1. 画像素材が要る。定義は書けるが、絵は作れない。
できあがりが正しく見えているかも確認できない。

2. 標準の挙動を止める必要がある。
専用のサーフェスを出しても、里々が元の立ち絵に戻す。
つついた場所で分岐を書けば、内蔵のつつかれ反応が止まる。
何が止まり、何を止めるかは `internals.md`。

3. 終わったら戻す。止めたままにすると、通常の会話に影響が残る。

`surfaces.txt` と `descript.txt` の記法は引いて書く。

## 両方を使う

排他ではない。シェルに盤面を出し、バルーンに数値と文を出す、
という形になることが多い。

文字が要るなら、その部分はバルーンに出すしかない。

## 重ねて見せる

別々のウィンドウを重ねて、1つの画面に見せる型。
背景を前提とする形式（ノベル、アドベンチャー）のほか、
看板、枠、立ち絵の外に置く表示にも、分解して使える。

例として、ノベルゲームの画面を組む。

**伺かに背景という仕組みは無い**（→ `capabilities.md`「背景」）。
背景の絵を1体のキャラクターとして立て、その手前に本来のキャラクターを置く。
これで、背景・立ち絵・文が揃った画面になる。

### 割り当て

| | |
|---|---|
| 背景 | `\p[2]` など、空いているスコープ |
| 立ち絵 | `\0` `\1` をそのまま使う |
| 文 | バルーン |

別々のウィンドウなので、放っておくと前後がひっくり返り、別々に動く。
2つのタグで束ねる。

```
\0\![set,alignmenttodesktop,free]       本体側の吸着を外す
\p[2]\![set,alignmenttodesktop,free]    背景側の吸着を外す
\![set,zorder,b0,s0,s2]                 手前から順に　\0のバルーン → \0の立ち絵 → 背景
\![set,sticky-window,0,2]               \0 と背景がセットで動く
```

- **吸着を外さないと、縦に置けない**。既定は下吸着で、上下方向に動かせない。
  `sticky-window` で束ねても、動かせる方向だけが追従する。
  片方だけ吸着を残すと、横は付いてきて縦だけ置き去りになる
- `alignmenttodesktop` は現スコープにしか効かない。スコープごとに指定する
- `zorder` はバルーンも並べられる。`b` がバルーン、`s` が立ち絵。
  左に書いたものほど手前
- `sticky-window` は `\![move]` にも効く。背景を動かせば立ち絵が付いてくる
- 3つともゴースト終了まで有効。スクリプト1回で消えるタグとは寿命が違う
- 束ねる推奨数の上限（2〜3個程度）は `capabilities.md`「ウィンドウ」を参照
- **すでに組んだスコープを含めて指定し直すとエラーになる。**
  組み替えるなら `\![reset,…]` を先に通す

### 位置を合わせる

`\![move]` で、背景の上に立ち絵を置く。書式は引いて書く。

`\![move]` は基準点を選べる。どことどこを合わせるか（左上どうし、右下どうし）を
指定する引数がある。**座標の基準はタグごとに違うので、決めてかからない。**

### 文字の場所を決める

ノベルゲームの見た目は、背景の決まった位置に文字の領域があることで成立する。
バルーンは既定では立ち絵に追従し、利用者がドラッグで動かせる。

3つを決める。

| | |
|---|---|
| 接し方 | `\![set,balloonalign,bottom]` ── シェルの中央下に、バルーンの中央上が接する |
| そこからのずれ | `balloon.offsetx` `balloon.offsety` |
| 動かせなくする | `\![lock,balloonmove]` ⇄ `\![unlock,balloonmove]` |

ずれの指定には4つの経路があり、効く範囲も寿命も違う。

| 書く場所 | 効き方 |
|---|---|
| `surfaces.txt` | そのサーフェスにだけ効く。切り替えれば元に戻る |
| シェルの `descript.txt` | シェル全体に効く |
| `\![set,balloonoffset,x,y]` | 説明に寿命の記述が無い（SSP 2.9.38 実機では別トークへ移っても維持され、自動では戻らない） |
| 里々の `＄BalloonOffset0` `＄BalloonOffset1` | **当てにしない**。下記 |

位置はファイルに書く。

**`\![set,balloonoffset]` を画面の土台にしない。**
説明に寿命の記述が無く（SSP 2.9.38 実機では別トークでも維持される）、自動では元に戻らないため戻し忘れが起きる。

```
surfaces.txt          そのサーフェスにだけ効く
    balloon.offsetx,座標            本体・相方を問わない
    sakura.balloon.offsetx,座標     本体側だけ
    kero.balloon.offsetx,座標       相方側だけ

シェルの descript.txt  シェル全体に効く（ゴースト側 descript.txt にも記述可、シェル側優先）
    sakura.balloon.offsetx,座標
    kero.balloon.offsetx,座標
    char*.balloon.offsetx,座標      \p[*]（0=sakura、1=kero、2以降）
    char*.balloon.offsety,座標      同上
```

`surfaces.txt` に書くのが基本。ノベル画面用のサーフェスに書いておけば、
切り替えただけでバルーンが所定の位置に来る。
辞書からタグを出さなくてよく、戻し忘れも起きない。

背景を `\p[2]` に置くなら、`char*` の指定が要る。

#### ＄BalloonOffset は当てにしない

里々の仕様書（`system/vars-misc.md`）に載っており、`＄BalloonOffset0` と `＄BalloonOffset1` の両方を設定すると応答に `BalloonOffset` ヘッダが付くが、SSP 2.9.38 ＋ 里々 Mc206-9 の実機ではバルーン位置が変わることを確認できていない（`＄返信ヘッダ「BalloonOffset」` も同様）。土台にしない。位置はファイルに書く。

応答ヘッダとして返るため出力を見ても異常に見えず、値はセーブされるうえ、空を代入しても空白の `BalloonOffset:` ヘッダが残り続ける。

#### 位置を決めただけでは固定されない

どの経路で指定しても、**利用者がドラッグで決めた座標が加算される。**
動かせる状態のままだと、そのぶんずれる。

利用者の操作を奪うことになる。UKADOC が2箇所で「濫用しないこと」と注意している。

通常の会話と行き来するなら、タグで囲む。
専用画面の間だけ `\![lock,balloonmove]`、終わったら `\![unlock,balloonmove]`。
**`descript.txt` の `balloon.dontmove` は使わない**。そこで指定するとタグでは解除できず、
通常の会話のバルーンまで動かせないままになる。

ゴースト全体がその形式なら、`descript.txt` に `balloon.dontmove` を書く（常に固定するときだけ）。
ノベルゲームとして作られたゴーストのように、常にその画面でよいなら、解除する場面が来ない。
起動した時点でその状態になり、利用者が動かしたずれも起きない。

行き来する場合は、利用者が過去に動かしたぶんのずれが残るはずである（未確認）。
`\![lock,balloonmove]` が止めるのは、以後の操作だけである。
**位置がぴったり合うことを前提にしない。**

そのずれは、ゴーストのフォルダに残っている（→ `testing.md`「利用者の側に残るもの」）。
消せば初期状態に戻るが、位置以外も戻る。

見た目そのもの（半透明、横長）はバルーン側の作りなので、同梱して指定する
（→ `display.md`「形が前提になる画面だけ、推奨バルーンを指定する」）。

### 終わったら戻す

タグで変えたものは、すべて戻す。

```
\![reset,zorder]
\![reset,sticky-window]
\0\![set,alignmenttodesktop,default]
\p[2]\![set,alignmenttodesktop,default]
\![unlock,balloonmove]
\![set,balloonalign,none]
```

**どれもゴースト終了まで残る**。解除しないと、通常の会話へ持ち越す。
特に吸着は、戻し忘れるとゴーストが宙に浮いたままになる。

**戻し方が揃っていない。**`reset` のもの、`default` を指定するもの、`unlock` のもの、
既定値を書き直すものがある。タグごとに確認する。

`surfaces.txt` に書いたものは、戻す対象にならない。そのサーフェスにしか効かないので、
サーフェスを切り替えれば元に戻る。タグに頼る範囲を減らすほど、後始末が軽くなる。

常にこの構成でよいなら、タグではなく `descript.txt` に書く。
起動した時点でその状態になり、毎回指定しなくて済む。

### 要るもの

画像・推奨バルーンの考え方は「[シェルに出す](#シェルに出す)」および `display.md`「形が前提になる画面だけ、推奨バルーンを指定する」を参照。

## 時間で動かす

さくらスクリプトの列を、時間軸として使う型。
動かすものが何であれ、続けて動くものはこの形になる。カウントダウン、ひとりでに進む演出。

`＄○○タイマ` とは別物（`＄○○タイマ` は 1秒刻み・セーブされる → `syntax_ref.md`「特殊変数」）。

### 核心 ── さくらスクリプトの列を、タイムラインとして使う

位置を変えるタグとウェイトを交互に並べた1本の列を作り、最初の1回だけ返す。毎フレーム辞書を呼ぶ形にすると、往復に十数ミリ秒かかるため短い間隔が保てない。

```
\![anim,offset,<ID>,0,0]\_w[<間隔>]\![anim,offset,<ID>,0,15]\_w[<間隔>]…
```

**`\![anim,offset]` の効果は `\s[…]` を実行するまで続く。** サーフェスを切り替えたら指定し直す。

### 骨格と経過の計測

`\![anim,offset,…]` の中に半角 `,` が入るため、`while` の区切り文字は全角 `，` にする（→ `syntax_ref.md`「展開を遅らせる関数に、括弧で作った区切り文字を渡さない」）。また座標の初期値は半角になるよう `＄<現在Y><TAB>0` で代入する。

```
＠<画面描画>
（nop,（set,_i,（<経過数>）））（when,（<継続条件>）,\i[101]）φ
（while，（<継続条件>）
	，\![anim,offset,101,（<現在X>）,（<現在Y>）]\_w[（<描画間隔>）]\![embed,On_<経過カウント>]
	（nop,（set,<現在Y>,（calc,（<現在Y>） + （<速度>）））（set,_i,（calc,（_i） + 1）））
）\![raise,On_<終了イベント>]

＠On_<経過カウント>
（set,<経過数>,（calc,（<経過数>） + 1））
```

| 要素 | 役割と注意 |
|---|---|
| `（_i）` と `（<経過数>）` | 組み立ては一瞬で終わるため `（_i）`（動きの計算用）は先まで進み、`（<経過数>）`（現在位置の判定用）は `\![embed]` を踏むたびに後から追う。混ぜない |
| `\![embed,On_<経過カウント>]` | 再生位置は `（Status）` 等で問い合わせられないため、通過点を仕込んで現在フレームを数える。**1回十数ミリ秒かかる**ため `\_w` を詰めるとここが頭打ちになる |
| 割り込み時の再構築 | クリックに応答した瞬間、再生中の列は破棄される。**すべての状態（座標・経過数・取得済みフラグ等）を変数に持っておき**、応答内で状態を更新してから `\s[…]`＋`（<画面描画>）` で残りを組み立て直す |
| 重ねる絵の位置合わせ | `\![anim,offset]` が動かすのは**左上の座標**。別アニメーションと大きさが違う場合は差を足し引きする（ずれは画面を見ないと分からない） |
| 設定値の切り出し | 速度・描画間隔等は `＠` で先頭に置く（→ `patterns.md`「調整する値は、設定として先に置く」）。`\_w` の下限はテスターで測れないため、大きめの初期値にして「短くしすぎると乱れる」と性質だけコメントする |

### 3つの層が、別々に動いている

| 層 | 動き方 |
|---|---|
| さくらスクリプトの実行 | 1本の列。同時に2つは走らない |
| シェルのアニメーション再生 | SSP が独立して動かす。`\i[…]` を出したらスクリプトは次へ進む（別アニメを重ねても互いを止めない） |
| 辞書の呼び出し | `\![embed]` を踏んだときだけ起きる |

### surfaces.txt 側とクリック受け

```
animation101.interval,never
animation101.pattern0,overlay,<サーフェス番号>,0,0,0
animation101.pattern3,overlay,-1,1000000000,0,0
animation101.collision0,0,0,<幅>,<高さ>,<判定名>
```

- **`interval,never` を必ず指定する**（無いと SSP が自動で動かす）。`-1` と極端に長い待ちで消えない状態を保つ
- サーフェス直書きの `collision` は動かないが、アニメーションに付けた `collision` は `\![anim,offset]` に追従する
- 動くものをつかませるなら、反応が早い `OnMouseDown` と `＊0<判定名>つつかれ` の**両方**で同じ処理を呼ぶ（`OnMouseClick` は離した時で遅く、**`OnMouseDown` はダブルクリック条件を満たすと呼ばれないことがある**）。`whenlist` の左辺を空にすると `equal` 等の結果で分岐できる：

```
＠OnMouseDown
（whenlist，，（equal,（Ｒ４）,<判定名>），（<クリック処理>））

＊0<判定名>つつかれ
（<クリック処理>）
```

### 限界

出力の量（フレーム数に比例）、`\![embed]` の往復時間（十数ミリ秒で頭打ち）、物体の数（タグ数に比例）がいずれも「規模で破綻する」（→ `capabilities.md`）。小さく作って実機で確認する。

## 掴んで並べ替える

利用者にウィンドウを動かさせ、その結果を辞書の状態に変える型。
重なり判定（ドラッグ、`OnOverlap`）と、配置の再構成（`\![move]`）は独立しており、クリックで動かすなら後半だけを使う。

**位置は取れない**。分かるのは何と何が重なったかだけ（正確な位置が要るものは作れない）。

### 割り当て

- 台紙に `\p[0]`、動かすものに `\p[2]` 以降を割り当てる（`\1` は相方なので使わない）。消すときは `\s[-1]`
- `\![set,sticky-window,…]` で束ねて1枚に見せる（束ねる推奨数は2〜3個程度 → `capabilities.md`「ウィンドウ」）
- **実際のウィンドウ位置ではなく、順序・配置を変数で持ち**、画面はその変数から組み立て直す

### イベントの飛び方

**引いても分からない。実際に動かして記録したもの。**

| いつ | 飛ぶもの | 用途・注意 |
|---|---|---|
| 押した | `OnMouseDown` | 結合を解く（`compare_head` 等で対象判定し `\![reset,sticky-window]`） |
| 動かし始めた | `OnMouseDragStart` | |
| 動かしている間 | `OnMouseMove`、`OnOtherOverlap` | `OnOverlap` は飛ばない |
| 離した | `OnMouseDragEnd` | 並べ直し・再結合の起点。**`OnMouseUp` は飛ばない**（つつきと自然に分かれる） |
| 離した直後（重なり変化あり） | `OnOtherOverlap` → `OnOverlap` | 溜まっていた重なりがここで来る |
| 離した直後（重なり変化なし） | 来ない | `OnMouseDragEnd` だけで完結するため、**`OnMouseDragEnd` 側で必ず並べ直して再結合する** |
| 辞書が `\![move]` した後 | `OnOverlap` | 自分が起こした移動でも飛ぶ |

### 実装の骨格と非自明な罠

```
＠OnMouseDown
（whenlist，，（compare_head,（Ｒ４）,<判定接頭辞>），\![reset,sticky-window]）

＠OnMouseDragEnd
（when,（compare_head,（Ｒ４）,<判定接頭辞>）,（<並べ直す>））

＠OnOverlap
（when,（<並べ替え済みフラグ>） == 1
	,（set,<並べ替え済みフラグ>,0）
	,（nop,（split,（replace,（Ｒ０）,-,_）,（バイト値,1））…）（set,<並べ替え済みフラグ>,1）（<並べ直す>）

＠<並べ直す>
\t（各スコープへ \s[…]）\![reset,sticky-window]\![reset,zorder]\_w[10]\p[2]\![move,--X=…,--Y=…,--base=0,--base-offset=left.top,--move-offset=left.top]\_w[10]\![set,zorder,…]\![set,sticky-window,…]
```

1. **重なりの読み方（`OnOverlap`）**: `（Ｒ０）` に現在の重なり、`（Ｒ１）` に1つ前の重なりが `0-2` のようなスコープ組の `0x01` 区切りで入る。**`-` を `_` 等へ `replace` してから `split` する**（`3-6` が式として評価され壊れるため）。台紙（スコープ0）との常時重なりは `（at,（Ｓ（Ｃ０））,0） != 0` で除外する。
2. **自己 `\![move]` の除外**: 並べ直しの `\![move]` でも `OnOverlap` が起きるため、入れ替え実行時にフラグを立て、次の `OnOverlap` で1回捨ててフラグを倒す。
3. **並べ直しの順序と `\_w[10]`**: 束ねたまま `\![move]` すると全部が一緒に動くため先に `\![reset,sticky-window]` で解く。**移動完了前に次の固定タグが届くと先に固定されることがあるため、各段の間に `\_w[10]` を置く**。`--base=0` と `--base-offset=left.top --move-offset=left.top` で台紙の左上基準に合わせる。
4. **`surfaces.txt` のカーソル固定**: 台紙（`\0`）の `cursor` セクションで矢印に固定する。**第2引数が `collision` の名前と一致しないとエラーにならず黙って効かない。**
   ```
   sakura.cursor
   {
   	mouseup0,<台紙判定名>,system:arrow
   	mousedown0,<台紙判定名>,system:arrow
   }
   ```

### 限界

束ねる数（2〜3個推奨）、判定の粗さ（重なり有無のみ）、ウィンドウ数（`\![move]` の列長）、掴んだ位置が取れない点の4つに制限される。
