# 専用画面のアーキテクチャ

通常の会話とは違う画面（ミニゲーム、ステータス画面、特殊メニュー）を作るとき、
表示を置ける場所は2つしかない。

どちらを選ぶかで、用意するもの・崩れ方・確かめられる範囲が変わる。
ここにあるのは、その選択のための材料と、組み合わせないと成立しない型である。

**型は、そのまま当てはめるものではない。**
依頼を要素に分け、必要な部分だけを取り出す。

```
「掴んで並べ替える」から重なりの部分を外すと、クリックで動かす仕組みになる
「時間で動かす」から動きを外すと、間を置いて起きるだけのものになる
```

丸ごと持ってくると、要らない仕組みまで抱え込む。
どの型にも、分けられる境目がある。それぞれの節の冒頭に書いてある。

ここにある3つが全部ではない。分けて、組み直せば、書かれていないものも作れる。

バルーンに描くタグは `display.md`、里々の内蔵挙動は `internals.md`。
`surfaces.txt` `descript.txt` の記法は**仕様を引いて書く。**

## 2つの類型

| | バルーンに出す | シェルに出す |
|---|---|---|
| 表示するもの | 文字と画像 | サーフェスの画像 |
| 位置の決め方 | 文字送りのカーソルを動かす | `surfaces.txt` の座標 |
| 操作の受け方 | 選択肢 → `OnChoiceSelect` | 当たり判定 → `OnMouseDoubleClick` |
| 用意するもの | 辞書と画像素材 | 画像素材と `surfaces.txt` |
| 見え方 | 利用者のフォントとバルーンの大きさで変わる | ピクセルで決まる。崩れない |

---

## バルーンに出す

文字を並べて形を作る。枠も、表も、メニューも、バーも、すべて文字で組む。

| | |
|---|---|
| 向く | 一覧、メニュー、数値の表示、テキストで進むもの |
| 向かない | 位置が正確に決まっていないと成立しないもの |

辞書だけで閉じる。画像素材が要らず、書いたものをそのまま確かめられる。

崩れる原因は利用者の側にある。フォントもバルーンの大きさも、ゴーストの作者は決められない。
桁を揃えた表は、別のバルーンでは崩れる。

書き方は `display.md`。複数のデータを並べるなら `patterns.md`。

---

## シェルに出す

専用のサーフェスを用意し、当たり判定を置いて、つついた場所で分岐する。

| | |
|---|---|
| 向く | 盤面、ボタン、絵として成立させたいもの |
| 向かない | 文字。サーフェスに文字は出せない |

### 組み立て

```
surfaces.txt   専用のサーフェスと、当たり判定（collision）を定義する
               辞書から動かすものは animation*.interval,never にしておく
辞書           \s[ID]  サーフェスを切り替える
               \i[ID]  定義済みのアニメーションを呼ぶ
               つついた部位で分岐する（OnMouseDoubleClick）
```

**`never` は自動では再生されない。**辞書から呼ぶものをこれにしておかないと、
SSP が独自のタイミングで動かす。

着せ替えも表示の切り替えに使える。`descript.txt` の `bindgroup` に定義すれば
`\![bind,…]` で着脱でき、`menuitem` に載せなければ利用者の着せ替えメニューには並ばない。
見せる着せ替えと、機能のための着せ替えを分けられる。

見た目は崩れない。代わりに3つのコストがかかる。

1. 画像素材が要る。定義は書けるが、絵は作れない。
できあがりが正しく見えているかも確認できない。

2. 標準の挙動を止める必要がある。
専用のサーフェスを出しても、里々が元の立ち絵に戻す。
つついた場所で分岐を書けば、内蔵のつつかれ反応が止まる。
何が止まり、何を止めるかは `internals.md`。

3. 終わったら戻す。止めたままにすると、通常の会話に影響が残る。

`surfaces.txt` と `descript.txt` の記法は引いて書く。

## 両方を使う

排他ではない。シェルに盤面を出し、バルーンに数値と文を出す、
という形になることが多い。

文字が要るなら、その部分はバルーンに出すしかない。

## 重ねて見せる

別々のウィンドウを重ねて、1つの画面に見せる型。
背景を前提とする形式（ノベル、アドベンチャー）のほか、
看板、枠、立ち絵の外に置く表示にも、分解して使える。

例として、ノベルゲームの画面を組む。

**伺かに背景という仕組みは無い**（→ `capabilities.md`「背景」）。
背景の絵を1体のキャラクターとして立て、その手前に本来のキャラクターを置く。
これで、背景・立ち絵・文が揃った画面になる。

### 割り当て

| | |
|---|---|
| 背景 | `\p[2]` など、空いているスコープ |
| 立ち絵 | `\0` `\1` をそのまま使う |
| 文 | バルーン |

別々のウィンドウなので、放っておくと前後がひっくり返り、別々に動く。
2つのタグで束ねる。

```
\0\![set,alignmenttodesktop,free]       本体側の吸着を外す
\p[2]\![set,alignmenttodesktop,free]    背景側の吸着を外す
\![set,zorder,b0,s0,s2]                 手前から順に　\0のバルーン → \0の立ち絵 → 背景
\![set,sticky-window,0,2]               \0 と背景がセットで動く
```

- **吸着を外さないと、縦に置けない。**既定は下吸着で、上下方向に動かせない。
  `sticky-window` で束ねても、動かせる方向だけが追従する。
  片方だけ吸着を残すと、横は付いてきて縦だけ置き去りになる
- `alignmenttodesktop` は現スコープにしか効かない。スコープごとに指定する
- `zorder` はバルーンも並べられる。`b` がバルーン、`s` が立ち絵。
  左に書いたものほど手前
- `sticky-window` は `\![move]` にも効く。背景を動かせば立ち絵が付いてくる
- 3つともゴースト終了まで有効。スクリプト1回で消えるタグとは寿命が違う
- 数に制限は無いが、公式の推奨は2〜3個（`\![set,zorder]` `\![set,sticky-window]` の説明にある）
- **すでに組んだスコープを含めて指定し直すとエラーになる。**
  組み替えるなら `\![reset,…]` を先に通す

### 位置を合わせる

`\![move]` で、背景の上に立ち絵を置く。書式は引いて書く。

`\![move]` は基準点を選べる。どことどこを合わせるか（左上どうし、右下どうし）を
指定する引数がある。**座標の基準はタグごとに違うので、決めてかからない。**

### 文字の場所を決める

ノベルゲームの見た目は、背景の決まった位置に文字の領域があることで成立する。
バルーンは既定では立ち絵に追従し、利用者がドラッグで動かせる。

3つを決める。

| | |
|---|---|
| 接し方 | `\![set,balloonalign,bottom]` ── シェルの中央下に、バルーンの中央上が接する |
| そこからのずれ | `balloon.offsetx` `balloon.offsety` |
| 動かせなくする | `\![lock,balloonmove]` ⇄ `\![unlock,balloonmove]` |

ずれの指定には4つの経路があり、効く範囲も寿命も違う。

| 書く場所 | 効き方 |
|---|---|
| `surfaces.txt` | そのサーフェスにだけ効く。切り替えれば元に戻る |
| シェルの `descript.txt` | シェル全体に効く |
| `\![set,balloonoffset,x,y]` | そのスクリプト1回（`\e` まで）。維持されない |
| 里々の `＄BalloonOffset0` `＄BalloonOffset1` | **当てにしない。**下記 |

位置はファイルに書く。

**`\![set,balloonoffset]` を画面の土台にしない。**
説明に寿命の記述が無いので、そのスクリプト限りで消える。
トークごとに出し直すことになる。

```
surfaces.txt          そのサーフェスにだけ効く
    balloon.offsetx,座標            本体・相方を問わない
    sakura.balloon.offsetx,座標     本体側だけ
    kero.balloon.offsetx,座標       相方側だけ

シェルの descript.txt  シェル全体に効く
    sakura.balloon.offsetx,座標
    kero.balloon.offsetx,座標
    char*.balloon.offsetx,座標      2人目以降　★仕様書に無い
    char*.balloon.offsety,座標      同上
```

`surfaces.txt` に書くのが基本。ノベル画面用のサーフェスに書いておけば、
切り替えただけでバルーンが所定の位置に来る。
辞書からタグを出さなくてよく、戻し忘れも起きない。

背景を `\p[2]` に置くなら、`char*` の指定が要る。
**仕様書に載っていないので、引いても出てこない。0件を「無い」と読まない。**

#### ＄BalloonOffset は当てにしない

里々Wiki に載っているが、実機で位置が変わることを確認できていない。
土台にしない。位置はファイルに書く。

応答ヘッダとして返るので、出力を見ても異常に見えない。
セーブされ、値を変えることしかできない（タブ区切りの行では空にできない）。

#### 位置を決めただけでは固定されない

どの経路で指定しても、**利用者がドラッグで決めた座標が加算される。**
動かせる状態のままだと、そのぶんずれる。

利用者の操作を奪うことになる。UKADOC が2箇所で「濫用しないこと」と注意している。

通常の会話と行き来するなら、タグで囲む。
専用画面の間だけ `\![lock,balloonmove]`、終わったら `\![unlock,balloonmove]`。
**`descript.txt` の `balloon.dontmove` は使わない。**そこで指定するとタグでは解除できず、
通常の会話のバルーンまで動かせないままになる。

ゴースト全体がその形式なら、`descript.txt` に書く。
ノベルゲームとして作られたゴーストのように、常にその画面でよいなら、解除する場面が来ない。
起動した時点でその状態になり、利用者が動かしたずれも起きない。

行き来する場合は、利用者が過去に動かしたぶんのずれが残るはずである（未確認）。
`\![lock,balloonmove]` が止めるのは、以後の操作だけである。
**位置がぴったり合うことを前提にしない。**

そのずれは、ゴーストのフォルダに残っている（→ `testing.md`「利用者の側に残るもの」）。
消せば初期状態に戻るが、位置以外も戻る。

見た目そのもの（半透明、横長）はバルーン側の作りなので、同梱して指定する
（→ `display.md`「形が前提になる画面だけ、推奨バルーンを指定する」）。

### 終わったら戻す

タグで変えたものは、すべて戻す。

```
\![reset,zorder]
\![reset,sticky-window]
\0\![set,alignmenttodesktop,default]
\p[2]\![set,alignmenttodesktop,default]
\![unlock,balloonmove]
\![set,balloonalign,none]
```

**どれもゴースト終了まで残る。**解除しないと、通常の会話へ持ち越す。
特に吸着は、戻し忘れるとゴーストが宙に浮いたままになる。

**戻し方が揃っていない。**`reset` のもの、`default` を指定するもの、`unlock` のもの、
既定値を書き直すものがある。タグごとに確認する。

`surfaces.txt` に書いたものは、戻す対象にならない。そのサーフェスにしか効かないので、
サーフェスを切り替えれば元に戻る。タグに頼る範囲を減らすほど、後始末が軽くなる。

常にこの構成でよいなら、タグではなく `descript.txt` に書く。
起動した時点でその状態になり、毎回指定しなくて済む。

### 要るもの

画像は用意してもらう。背景の絵、場面ごとの差分、立ち絵。
定義は書けるが、絵は作れないし、できあがりが正しく見えているかも確認できない
（→ `capabilities.md`「確かめられる範囲」）。

横長のウィンドウのように、バルーンの形が前提になるなら、推奨バルーンを指定する
（→ `display.md`「形が前提になる画面だけ、推奨バルーンを指定する」）。

## 時間で動かす

さくらスクリプトの列を、時間軸として使う型。
動かすものが何であれ、続けて動くものはこの形になる。
カウントダウン、ひとりでに進む演出。

例として、落ちてくる物をクリックでつかむ画面を組む。

`＄○○タイマ` とは別物。

| | |
|---|---|
| `＄○○タイマ` | 1秒刻み。セーブされ、起動をまたぐ。後で1回やる（→ `syntax.md`） |
| この型 | ミリ秒刻み。そのスクリプト限りで、割り込まれると消える。続けて動かす |

「3秒後に喋る」はタイマ。「3秒かけて動かす」はこちら。

### 核心 ── さくらスクリプトの列を、タイムラインとして使う

さくらスクリプトは1本の列として先頭から順に実行される
（→ `capabilities.md`「実行の途中には手を出せない」）。
この「順に実行される」を時間軸として使う。

```
\![anim,offset,101,0,0]   \_w[50]
\![anim,offset,101,0,15]  \_w[50]
\![anim,offset,101,0,30]  \_w[50]
…
```

位置を変えるタグとウェイトを交互に並べた1本の文字列を作って返す。
SSP がそれを再生すると、50ms ごとに絵が動く。

**辞書が呼ばれるのは、最初の1回だけである。**
毎フレーム呼び出す形にすると、1回あたりの往復に十数ミリ秒かかるので、
短い間隔が保てない。全フレームぶんを先に組み立てて渡す。

**`\![anim,offset]` の効果は、`\s[…]` を実行するまで続く。**
サーフェスを切り替えると位置が戻るので、切り替えたら指定し直す。

### 骨格

```
＠ゲーム1描画
（nop,
	＃いまの座標と、組み立て中のフレーム番号
	（set,point1nowx,…）（set,point1nowy,…）
	（set,_i,（pastframe））
）（when，（point1get） == 0，\i[101]）φ
（while，まだ落ちきっていない
	，\![anim,offset,101,（point1nowx）,（point1nowy）]
	\_w[（キャッチ描画間隔）]\![embed,OnFrameCountCatchGame]
	（set,point1nowy,（point1nowy） + （when,（_i） >= （point1start）,（キャッチ落下速度）,0））
	（set,_i,（_i） + 1）
）\![raise,OnEndCatchGame]
```

| | |
|---|---|
| `（while,…）` | 繰り返しの結果が、そのまま出力される。ここでタグ列を積み上げる |
| `\_w[（キャッチ描画間隔）]` | 1フレームの長さ。設定にしておけば速さを調整できる |
| `（_i）` | 組み立て中のフレーム番号。`（pastframe）` とは別物（下記） |
| `（point1start）` | 落ち始めるフレーム。そこに届くまで座標を進めない |
| `\![raise,…]` | 列の最後に置く。再生し終わったら終了処理へ移る |
| `φ` | `＠` の中で行を分けるための改行止め |

### 3つの層が、別々に動いている

ここを取り違えると、競合を心配して作れなくなる。

| | 動き方 |
|---|---|
| さくらスクリプトの実行 | 1本の列。同時に2つは走らない |
| シェルのアニメーション再生 | SSP が独立して動かす。`\i[…]` を出したら、スクリプトは次へ進む |
| 辞書の呼び出し | `\![embed]` を踏んだときだけ起きる |

だから、落下の列を再生している最中に `\i[201]`（取得アニメーション）を出しても、
互いを止めない。

### 経過を数える ── `\![embed]`

**再生が「いまどこか」を、辞書から問い合わせることはできない。**
`（Status）` で分かるのは喋っている最中かどうかだけである。

代わりに、通過点を仕込む。

```
	\_w[（キャッチ描画間隔）]\![embed,OnFrameCountCatchGame]

＠OnFrameCountCatchGame
（set,pastframe,（pastframe） + 1）
```

`\![embed]` は、そこに到達した時点で辞書を呼ぶ。
1フレームごとに変数を増やせば、実時間で進む経過フレームが手に入る。

**呼び出しには十数ミリ秒かかる。**`\_w[…]` を詰めていくと、ここが先に頭打ちになる。

#### 2つの時間を取り違えない

| | |
|---|---|
| `（_i）` | `while` を回すたびに増える。これから再生される番号 |
| `（pastframe）` | `\![embed]` を踏むたびに増える。すでに再生された数 |

組み立ては一瞬で終わる。`（_i）` は先まで進んでいて、`（pastframe）` が後から追いかける。

動きのしかたを決めるのは `（_i）`、いまどこかを知るのは `（pastframe）`。

```
（set,point1nowy,（point1nowy） + （when,（_i） >= （point1start）,（キャッチ落下速度）,0））
```

`（point1start）` に届くまで落下速度を足さない。落ち始めがずれる。
届いていない間もタグは出力されるので、その場に止まって見える。

### 割り込まれたら、状態から組み立て直す

**クリックに応答した瞬間、再生中の列は破棄される。**
続きを再生させる方法は無いので、残りを作り直す。

```
＠ゲーム1ポイント1クリック
（when，（pastframe） >= （point1start）
	，\0\s[200]\i[201]\![anim,offset,201,（point1nowx）,（point1nowy）]
	（set,point1get,1）
	（ゲーム1描画）
）
```

1. 取得アニメーションを出す
2. 取ったことを変数に記録する
3. 描画をもう一度呼ぶ

呼び直された `（ゲーム1描画）` は、`（point1get） == 0` が偽になるので
1番を出力しない。座標も経過フレームも変数に残っているので、続きから組み立てられる。

**状態をすべて変数に持っておくことが条件になる。**
再生中の列に情報を持たせると、破棄された時点で失われる。

この例では、先頭で `\s[200]` を出し直している。
サーフェスを切り替えるとオフセットが消えるが、続く `（ゲーム1描画）` が全部を指定し直すので、
結果として揃う。

#### 重ねる絵の位置を合わせる

**`\![anim,offset]` が動かすのは、左上の座標である。**

```
\![anim,offset,201,（point1nowx）,（point1nowy）]
```

落下する絵と、取得時のアニメーションで大きさが違うと、同じ座標を渡してもずれる。
差のぶんを足し引きして合わせる。

**ずれているかどうかは、画面を見ないと分からない。**
組んだら利用者に確認を頼む（→ `capabilities.md`「確かめられる範囲」）。

### surfaces.txt 側

```
animation101.interval,never
animation101.pattern0,overlay,201,0,0,0
animation101.pattern3,overlay,-1,1000000000,0,0
animation101.collision100,0,0,20,20,point1
```

| | |
|---|---|
| `interval,never` | **辞書から呼ぶものは、必ずこれにする。**でないと SSP が勝手に動かす |
| `pattern0,overlay,201,0,0,0` | 重ねる絵。待ち時間 0 |
| `pattern3,overlay,-1,…` | `-1` は消す指定。極端に長い待ちを付けて、実質消えないようにする |
| `collision100,…,point1` | 当たり判定。`\![anim,offset]` で動かすと、判定も一緒に動く |

動く当たり判定は、これで作る。
サーフェスに直接書いた `collision` は動かないが、アニメーションに付けた判定は追従する。

### クリックを受ける

```
＠OnMouseDown
（whenlist，
	，（equal,（R4）,point1），（ゲーム1ポイント1クリック）
	…
）

＊0point1つつかれ
（ゲーム1ポイント1クリック）
```

2つの経路で受けている。

| | |
|---|---|
| `OnMouseDown` | 押し下げた時。反応が早い |
| `＊0<判定名>つつかれ` | 里々の内蔵処理を通る経路（→ `internals.md`） |

`OnMouseClick` 系は離した時なので、動くものをつかませる用途には遅い。
ただし **`OnMouseDown` は、ダブルクリックの条件を満たすと呼ばれないことがある。**
両方に同じ処理を向けておく。

`（whenlist）` の左辺を空にして、`（equal,…）` の結果をそのまま条件に使っている。

### 調整する値を、先頭に出す

速さ、落ちる間隔、終わる位置 ── 触りたくなる値を、処理の中に埋めない。
`＠` で定義して、ファイルの先頭にまとめる
（→ `patterns.md`「調整する値は、設定として先に置く」）。

```
＠キャッチ落下速度
15

＃小さくすると速くなる。短くしすぎると動きが乱れる
＠キャッチ描画間隔
50

＠キャッチ落ち始めのばらつき
50

＃シェルより少し大きめにする
＠キャッチ終わる位置
420
```

処理部からは `（キャッチ描画間隔）` のように読む。
利用者が書き換えるのは、名前の下の1行だけになる。
括弧の中を編集させると、**カンマや括弧が欠けて黙って動かなくなる。**

| | |
|---|---|
| 名前は長く、役割が分かる形にする | 短い名前は既存の定義とぶつかる（→ `syntax.md`「名前空間を共有する」） |
| 機能の名前を頭に付ける | 既にある辞書に足しても、ぶつからない |
| 日本語で書く | 名前に制限は無い。読むのはゴーストの作者なので、略語より通じる |
| 1行だけ書く | 複数行あると、そのうち1つがランダムに選ばれる |
| 同じ名前の変数を作らない | 名前空間を共有していて、片方が読めなくなる |

名前が説明を兼ねるので、コメントは「何を書くと壊れるか」だけでよい。

**描画の間隔には下限がある。**1フレームごとに `\![embed]` で辞書を呼んでいるので、
その往復より短くすると間に合わなくなる。

**往復にかかる時間は測れない。**SSP が里々を呼ぶ時間なので、テスターでは分からない
（→ `testing.md`「確かめられないこと」）。
大きめの値を初期値に置き、どこまで下げられるかは利用者に試してもらう。

境目を知っているなら、それを書く。
「30より小さくしない」で足り、**なぜその値なのかは書かない。**
知らないなら「短くしすぎると動きが乱れる」のように、性質だけを書く。

### 限界

| | |
|---|---|
| 出力の量 | フレーム数ぶんのタグが1本の文字列になる。長い動きほど伸びる |
| `\![embed]` の間隔 | 1回ごとに十数ミリ秒かかる。`\_w[…]` を詰めても、そこで頭打ちになる |
| 物体の数 | 1フレームあたりのタグが数に比例して増える |

どれも「規模で破綻する」の形をしている（→ `capabilities.md`）。
小さく作って、実際に動かして確かめる。

## 掴んで並べ替える

利用者にウィンドウを動かさせ、その結果を辞書の状態に変える型。
並べ替え、仕分け、置き場所を選ばせるもの。

この型は2つに分けられる。
重なりで判定する部分（ドラッグ、`OnOverlap`）と、
配置を変数で持って並べ直す部分（`\![move]`）は、互いに依存していない。
クリックで動かすなら、後半だけを使う。スライドパズルがその形になる。

例として、8枚のメモを並べ替えるノートを組む。
この例は、公式の推奨する数を超えている（→ [限界](#限界-1)）。減らせるなら減らす。

**位置は取れない。**分かるのは何と何が重なったかだけである。
ジグソーパズルのように、正確な位置が要るものは作れない。

### 割り当て

| | |
|---|---|
| 台紙 | `\p[0]` |
| 動かすもの | `\p[2]`〜`\p[9]` に1つずつ |

全部が別のウィンドウである。`\![set,sticky-window,…]` で束ねると、1枚の紙に見える。
`\1` は相方なので使わない。

順序は変数で持つ。`（メモ位置0）`〜`（メモ位置7）` が「上から何番目か」を保持し、
画面はその値から組み立て直す。ウィンドウの実際の位置は状態ではない。

### イベントの飛び方

**引いても分からない。実際に動かして記録したもの。**

| いつ | 飛ぶもの | |
|---|---|---|
| 押した | `OnMouseDown` | 結合を解く |
| 動かし始めた | `OnMouseDragStart` | |
| 動かしている間 | `OnMouseMove`、`OnOtherOverlap` | `OnOverlap` は飛ばない |
| 離した | `OnMouseDragEnd` | 結合し直す。`OnMouseUp` は飛ばない |
| 離した直後（重なりが変わった） | `OnOtherOverlap` → `OnOverlap` | 溜まっていた重なりがここで来る |
| 離した直後（重なりが変わらない） | 来ない | `OnMouseDragEnd` だけで完結する |
| 辞書が `\![move]` した後 | `OnOverlap` | 自分が起こしたぶん |

**途中で何枚の上を通っても、入れ替わらない。**判定されるのは離した瞬間の重なりだけである。

**`OnMouseUp` に処理を書いても、ドラッグしたときは実行されない。**
つついたときだけ動く。掴んで動かす操作と、つつく操作が、自然に分かれる。

### 掴む瞬間に解く

```
＠OnMouseDown
（when，（compare_head,（Ｒ４）,メモ），\![reset,sticky-window]）
```

束ねたままだと、1枚掴んで全部が動く。
台紙を掴めば全部、メモを掴めばそれだけ ── 同じ設定の on/off で切り替わる。

### 重ならなかったときに戻す

**`OnOverlap` は、重なりが変化したときにしか来ない。**
掴んで動かしても、どれとも重ならなければ飛ばない。

そのままでは、掴んだものがずれた位置に残り、束ねも解けたままになる。

```
＠OnMouseDragEnd
（when，（compare_head,（Ｒ４）,メモ），（メモを並べ直す））
```

**離したら必ず並べ直す。**これが結合し直す経路になる。

### 重なりの読み方

```
Reference0   いまの重なり      0-2 0-3 … 3-6
Reference1   ひとつ前の重なり   0-2 0-3 …
```

スコープ番号の組が 0x01 区切りで連なる。`Reference1` と比べれば、増えた組が分かる。

```
（split,（replace,（Ｒ０）,-,_）,（バイト値,1））
```

**`-` を潰してから分ける。**`3-6` が式として評価され、値が壊れる。

台紙との重なりは捨てる。組の片方がスコープ0なら飛ばす。
台紙とは常に重なっている。

```
（at,（Ｓ（Ｃ０））,0） != 0
```

### 自分が起こした移動を捨てる

並べ直すと `\![move]` が走り、それがまた `OnOverlap` を起こす。
**利用者が動かしたのか、自分が動かしたのかを、イベントは区別しない。**

```
＠OnOverlap
（when，（メモ並べ替え済み） == 1
	，（set,メモ並べ替え済み,0）
	，（重なった2枚を入れ替える）（set,メモ並べ替え済み,1）（メモを並べ直す）
）
```

入れ替えたら立て、次の1回で倒す。

### 並べ直す順序

```
\t                                          割り込みを止める
各スコープに \s[…]                           絵を出す
\![reset,sticky-window] \![reset,zorder]     束ねを解く
\p[…]\![move,--X=…,--Y=…,--base=0,…]         1枚ずつ配置する
\![set,zorder,…] \![set,sticky-window,…]     結び直す
```

**解かないと動かせない。**束ねたまま `\![move]` すると、全部が一緒に動く。

各段の間に `\_w[10]` を置く。
**SSP がウィンドウを動かし終える前に次のタグが届くと、固定が先に起きることがある。**

`--base=0` で台紙を基準にし、`--base-offset=left.top --move-offset=left.top` で左上どうしを合わせる。

### surfaces.txt 側

```
surface11000                        メモ1枚
{
	element0,base,memo0.png,0,0
	collision0,0,0,272,46,メモ0
}

sakura.cursor                       台紙（\0）のカーソル
{
	mouseup0,台紙,system:arrow
	mousedown0,台紙,system:arrow
}
```

当たり判定の名前で、どれが掴まれたかを見分ける。`compare_head` で前方一致させれば、
何枚あってもまとめて扱える。

台紙のカーソルは矢印に固定する。指定しないと、掴める見た目のまま変わらない。
`mouseup` の第2引数は `collision` で付けた名前である。
書いた名前が定義されていなくてもエラーにならず、**指定が黙って効かない。**

消すときは `\s[-1]`。ウィンドウごと消える。

### 限界

| | |
|---|---|
| 束ねる数 | 公式の推奨は2〜3個（`\![set,zorder]` `\![set,sticky-window]` の説明）。8個で組んだ例では、時々 `zorder` が効かず、後ろに回ることがあった |
| 判定の粗さ | 重なったかどうかだけ。どこに、どれだけ重なったかは分からない |
| ウィンドウの数 | 1枚につき1つ要る。増えるほど `\![move]` の列が伸びる |
| 掴んだ位置 | 取れない。そのものの、どこを持ったかは分からない |

推奨から離れるほど、確かめる回数が要る。
**毎回は起きない。**1回動いたことを根拠にしない。
