# 里々で作るときの型

里々にはデータ構造が無い。配列も、連想配列も、ローカル変数も無い。
代わりに、引数の分割と、単語群と、名前の組み立てで同じことをする。

ここにあるのは、その組み方である。

通読する必要はない。次のようなときに引く。

- 一覧・メニュー・図鑑のように、複数のデータを持って表示する
- 件数が増えるものを記録する

何が無くて、代わりに何があるかは `syntax.md`。バルーンに出すタグは `display.md`。

## 一時変数

里々の変数はすべてグローバルで、終了時にセーブされる。
関数の中だけで使ったつもりの変数も残り続け、`satori_savedata.txt` に溜まる。

**`_` で始める名前にして、使い終わったら空を代入する。**

```
（nop,（set,_t,…））（_t）（set,_t,）
```

`_` で始まっているかどうかは里々にとって何の意味も持たない。
読む側が「これは作業用だ」と分かるためだけの規約である。

## データを持つ

### 1行を1つの変数に入れる

カンマ区切りの文字列を引数の位置に置くと、そのまま複数の引数に分かれる。

```
＄アイテム1	3,薬草,50,2          通し番号,名前,値段,個数

＠一覧表示
（A1）　（A2）円　×（A3）個

：（call,一覧表示,（アイテム1））
```

```
（A0）＝3　（A1）＝薬草　（A2）＝50　（A3）＝2
→ 薬草　50円　×2個
```

先頭の要素は `（A0）` に入る。`（Aの数）` が要素数になる。

配列という機能があるのではない。引数の分割そのものが配列アクセスになっている。

1レコードが変数1つに収まる。里々の変数はセーブデータに保存されるので、
これだけで構造体が永続化できる。レコードが複数なら `アイテム1`〜`アイテムN` と
連番の変数を作り、`（set,アイテム（C0）,…）` で回す。

### 取り出す

`（nswitch,位置,配列）`。**1始まり**なので、0始まりで数えるなら +1 する。

```
（nswitch,（calc,（i） + 1）,（アイテム1））
```

関数にするなら、引数参照の番号を組み立てる。

```
＃A0 インデックス（0始まり）
＃A1- カンマ区切りの配列
＠配列取得
（A（calc,（A0） + 1））
```

### 書き換える

全要素を走査し、該当位置だけ差し替えて `join` で繋ぎ直す。

```
＃A0 インデックス
＃A1 代入する値
＃A2- カンマ区切りの配列
＠配列格納
（join、,
	（for,2,（calc,（Aの数） - 1）,1,
		、（when,（calc,（C0） - 2） == （A0）
			,（A1）
			,（A（C0））
		）
	）
）
```

呼び出しは読んで・書き換えて・戻す。

```
（set,アイテム1,（call,配列格納,2,999,（アイテム1）））
```

`（Aの数）` は引数の総数。ここでは A0・A1 を除いた A2 以降が配列本体にあたる。

### 代入で割れる

書き方で結果が変わる。

| | |
|---|---|
| `＄アイテム1<TAB>3,薬草,50,2` | タブ区切り。カンマのまま入る |
| `（set,アイテム1,3,薬草,50,2）` | **引数が割れて、代入そのものが失敗する** |
| `（set（バイト値,1）アイテム1（バイト値,1）3,薬草,50,2）` | 入る |

**カンマ区切りを引数として渡すと、必ず分割される。**
分割させたくない引数がある関数では、引数区切りを `（バイト値,1）` にする
（→ `syntax.md`「引数区切りの誤爆」）。

空要素は空文字のまま残る（`,,,`）。判定は `（is_empty,…）`。

### 行に一意の番号を持たせる

レコードの中に、その行だけの番号を入れておく。理由は3つとも実害がある。

- 並べ替えると添字が入れ替わる。`アイテム3` が同じ行を指し続ける保証はない
- マスタから複製した行は内容が同じになる。同じ道具を2つ持てば区別できない
- 単語の追加では、同じ内容の行を2つ持てない（→ [行数が変わる表](#行数が変わる表)）

番号は増やし続けるカウンタから取る。消えた分を再利用しない。

```
（set,通し番号,（通し番号） + 1）
（set,アイテム（C0）,（種類番号）,（名前）,（値段）,（通し番号））
```

マスタの番号と、行の番号は別物。
「どの種類か」と「どの個体か」を、1つの列で兼ねさせない。

### 日付の差を取る

里々に日付の引き算は無い。通日に直してから引く。

```
＠現在通算秒
（nop,
	（set,_vy,（calc,（現在年）-2000-（when,（現在月）<=2,1,0）））
	（set,_vm,（calc,（現在月）+（when,（現在月）<=2,12,0）））
	（set,_d,（calc,365*（_vy）+（_vy）/4-（_vy）/100+（_vy）/400+306*(（_vm）+1)/10+（現在日）-428））
）（calc,((（_d）*24+（現在時）)*60+（現在分）)*60+（現在秒））（set,_vy,）（set,_vm,）（set,_d,）
```

```
＄tmp＝（現在通算秒）
＄時刻差＝（calc,（tmp）-（起動時刻））
＄起動時刻＝（tmp）
＄tmp＝
```

基準は 2000 年。桁を落とすためと、400 の倍数だから
（→ `syntax.md`「calc の結果が整数に丸められる」）。
**400 の倍数でない年にすると、うるう年の判定が狂う。**

**`（現在通算秒）` は1回だけ呼ぶ。**2回呼ぶと、その間に秒が変わることがある。

## 表を持つ

### 単語群がテーブルになる

```
＠アイテム表
1,薬草,50,回復
2,鉄の剣,300,武器
```

1行が1レコード。`（アイテム表）` でランダムに1件、
`（単語群「アイテム表」の数）` で件数、`for` で全件走査。

変わらないマスタデータはここに置く。

### 行数が変わる表

`（単語の追加,単語群名,単語）` は、その単語群が無ければ新しく作る。
追加した分は `satori_savedata.txt` に `＠単語群名` として保存され、次の起動で復元される。

連番の変数と違い、上限を先に決めなくてよい。入手したもの、訪れた場所、
記録した日付のように、件数が増えていく表はこれで持てる。

```
（nop,（単語の追加（バイト値,1）所持品（バイト値,1）1,薬草,50））
```

1行をカンマ区切りにするなら、引数区切りを `（バイト値,1）` にする。
そのまま書くと、行の中のカンマで引数が割れる。

| | |
|---|---|
| 追加位置 | 末尾 |
| 同じ内容の二重追加 | されない。件数が増えない |
| 削除 | `（追加単語の削除,単語群名,単語）`。完全一致のみ |
| 辞書に書いた単語 | 削除できない。消せるのは追加した分だけ |
| 削除して再追加 | 末尾へ移る。順序が変わる |

**行を書き換える手段が無い。**削除して追加し直すことになり、その行は末尾へ移る。
順序に意味があるなら、行の先頭に並べ替え用の値を持たせ、読む側で並べ替える。

### 順序を固定して読む

**単語群は既定でランダムに選ばれる。**表として読むには順序を固定する。

```
＄単語群「所持品」の重複回避	無効、起動中
＄単語群「所持品」の重複回避	降順、起動中
：（for,1,（単語群「所持品」の数）,1,（call,1行表示,（所持品）））
```

- 「降順」が先頭から後ろへ。「昇順」は最後尾から前へ。**名前が直感と逆**
- 設定は2行要る。すでに「降順」のときにもう一度「降順」を設定しても、
  読む位置は先頭に戻らない。一度「無効」にしてから設定し直す
- 走査を途中でやめると、次の走査はその続きから始まる

### 存在を確かめてから読む

**存在しない単語群を呼ぶと、その文字列がそのまま出る。**

```
（空表） → （空表）
```

エラーにならない。`（空表）` という文字がバルーンに出る。
`（単語群「空表」の存在）` で確かめてから読む。

### count で探すときは前後に区切りを付ける

`（count,一覧,（ID））` で存在を調べると、**`1` が `11` にも一致する。**

保存するときに前後を区切りで挟み、探すときも挟む。

```
＄一覧	,（Ｒ０）,
（count（バイト値,1）（一覧）（バイト値,1）,（ID）,）
```

`count` の引数にカンマが入るので、引数区切りを `（バイト値,1）` にする。

## 選ぶ・配る

### 分岐の結果として配列を返す

`whenlist` の返り値をカンマ区切りにすれば、分岐の結果として配列を返せる。

```
＠段階別の必要値
（whenlist、（A0） ==
	、0、0,40,30,66
	、1、50,103,60,40
）
```

関数の返り値をそのまま配列として扱えるので、中間変数が要らない。

```
（call,配列取得,2,（call,段階別の必要値,（進行度）））
```

### 選択肢に丸ごと渡す

```
\__q[On_Select_Item,（アイテム1）]（call,一覧表示,（アイテム1））\__q
```

受け側では `（Ｒ０）`〜`（Ｒ３）` に分かれて入る。
選んだレコードを、次のイベントへそのまま運べる。変数に退避しなくてよい。

### 重複なしで引く

```
＄単語群「名前」の重複回避	有効、起動中
```

その単語群から、全部引くまで同じものが出ない。
応用として、`0`〜`51` の連番を単語群にすれば、引いた値の商（`/ 13`）でスート、余り（`% 13`）で数字が求まるため、トランプの再現となる。

リセットは、別のルールに変更してから再設定する（→ [順序を固定して読む](#順序を固定して読む)）。

## 画面を作る

### レイアウトを計算する

1行に何個入るかは、バルーンによって変わる（→ `display.md`「大きさは実行時に決まる」）。
固定で決めず、**表示可能な幅を取ってから計算する。**

ただし、この情報はSSPにしかなく、テスターでは取れない（→ `testing.md`「SSP にしか無い情報を取る」）。
値が取れなかったときの既定を決めておく。

### 調整する値は、設定として先に置く

ini や設定ファイルにあたるものを、里々の中で作る手法である。
別形式のファイルも、それを読む仕組みも要らない。

```
＠Onリストの表示項目数
6

＠Onリストの次へ
 >
```

処理部からは `（Onリストの表示項目数）` で読む。

設定をファイルの先頭にまとめ、処理は下に置く。
利用者が目にするのは設定だけで済み、処理部は読まなくてよい。

#### 設定にしたら、何を書くと壊れるかを添える

「半角カンマを使わない」「1行に収まる長さにする」のように、
その値が処理のどこへ入るかから決まる。

数値には、動かなくなる境目を書く。
「小さくすると速くなる」だけでは、どこまで小さくできるか分からない。

余裕を見た値を境目にする。限界そのものを書くと、その手前で不具合が出る。

境目が分からないなら、書かない。
ベースウェアとのやりとりが絡むものは、こちらでは測れない
（→ `testing.md`「確かめられないこと」）。
そのときは「短くしすぎると動きが乱れる」のように、性質だけを書く。
**知らない値を推測で書かない。**

なぜその値なのかは書かない。内部の事情であって、調整する側には関係がない。

専門用語を使わない。設定を読むのはゴーストの作者であって、
プログラムを書く人とは限らない。

## 同じ処理を、複数の対象に使う

名前を組み立てれば、処理は1つで済む。

対象の名前を変数に入れ、その値を定義名の一部として使う。

```
＄リストの名前	アイテム一覧

（（リストの名前）の1ページ件数）   →  （アイテム一覧の1ページ件数）
（（リストの名前）の説明）          →  （アイテム一覧の説明）
```

二重の括弧。内側が展開されてから、外側が名前として読み直される
（→ `syntax.md`「評価モデル」）。

### 設定をまとめて、処理の外に出す

呼ぶ側は、名前を決めて、その名前で始まる定義を並べるだけになる。

```
＄リストの名前	アイテム一覧
（リストを表示）

＠アイテム一覧の1ページ件数
6

＠アイテム一覧の説明
持っているものの一覧です。

＠アイテム一覧の項目
くすり
つるぎ
たて
```

処理部は1つ。別の一覧を足すときは、名前を変えて定義を並べるだけで、処理部に触らない。

一覧の持ち方は[表を持つ](#表を持つ)。

設定を足しても処理部が壊れない。
これが直しやすさの最も強い形になる（→ `dialogue.md`「直しやすく作る」）。

### 名前に使えない文字を、先に伝える

組み立てた名前は、そのまま選択肢の ID や引数になる。

| | |
|---|---|
| 引数の区切りになる文字 | `,` `、` `，` `､`（→ `syntax.md`「引数区切りの誤爆」） |
| 選択肢の ID に使うなら | `On` で始める。でないと里々が ID を書き換える（→ `internals.md`） |
| `replace_after.txt` の置換対象 | 出力の直前に置き換わる（→ `internals.md`） |

**利用者が名前を決めるので、書く前に伝える。**
