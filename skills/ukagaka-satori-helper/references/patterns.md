# 里々で作るときの型

里々にはデータ構造が無い。配列も、連想配列も、ローカル変数も無い。
代わりに、引数の分割と、単語群と、名前の組み立てで同じことをする。
ここにあるのは、その組み方と、作者が直しやすくする値の置き方である。
多くは `syntax.md` から導けるが、組み立て直す手間を省くために置いている。

通読する必要はない。次のようなときに引く。

- 一覧・メニュー・図鑑のように、複数のデータを持って表示する
- 件数が増えるものを記録する
- 作者が後で変えたくなる値を置く

## 一時変数

変数はすべて終了時にセーブされる。作業用の変数も `satori_savedata.txt` に溜まる。
名前を `_` で始め、使い終わったら空を代入して消す。`_` は読む側のための目印で、里々にとって意味は無い。

```
（nop,（set,_t,…））（_t）（set,_t,）
```

## データを持つ

1件をカンマ区切りで1つの変数に入れる。`call` の引数の位置に置くと、`（Ａ０）` 以降に分かれる。

```
＄アイテム1	3,薬草,50,2          通し番号,名前,値段,個数

＠一覧表示
（Ａ１）　（Ａ２）円　×（Ａ３）個

：（call,一覧表示,（アイテム1））    → 薬草　50円　×2個
```

- 代入は `＄名前<TAB>値` で行う。`set` に渡すと、値のカンマで引数が割れて代入されない。
  展開した結果にカンマが入る場合（`（set,名前,（アイテム1））` など）も同じ
- 要素数は `（Ａの数）`。空の要素は空のまま残る（`3,,50`）
- n番目を取り出すだけなら `（nswitch,位置,（アイテム1））`。位置は1始まり
- 選択肢の引数にそのまま置くと、選んだ先で `（Ｒ０）` 以降に分かれて届く（`\__q[On_Select_Item,（アイテム1）]…\__q`）
- 条件で配列を選ぶなら、`whenlist` の結果をカンマ区切りの値にする。区切りを `、` にして、値のカンマで割れないようにする
  （`（whenlist、（Ａ０） ==、0、0,40,30、1、50,103,60）`）
- 件数が決まっているなら、`アイテム1`〜`アイテムN` の連番の変数にする

### 取り出す・書き換える関数

```
＃A0 位置（0始まり）　A1- カンマ区切りの配列
＠配列取得
（Ａ（calc,（Ａ０） + 1））

＃A0 位置（0始まり）　A1 入れる値　A2- カンマ区切りの配列
＠配列格納
（join、,
	（for,2,（calc,（Ａの数） - 1）,1,
		、（when,（calc,（C0） - 2） == （A0）
			,（A1）
			,（A（C0））
		）
	）
）

＄アイテム1	（call,配列格納,2,999,（アイテム1））      → 3,薬草,999,2
```

`配列格納` は、`for` が出力する `、値、値…` を、`join` が `、` 区切りの引数として受け取り、`,` でつなぎ直している。
書き戻しも `＄名前<TAB>値` で行う。`set` では割れる。

## 単語群を表として使う

```
＠アイテム表
1,薬草,50,回復
2,鉄の剣,300,武器
```

1行が1件。件数は `（単語群「アイテム表」の数）`。変わらないデータはここに置く。

### 件数が増える表

`（単語の追加,単語群名,単語）` で足す。単語群が無ければ作られ、追加した分はセーブデータに `＠単語群名` として残る。
上限を先に決めなくてよい。

```
（nop,（単語の追加（バイト値,1）所持品（バイト値,1）1,薬草,50））
```

行にカンマを含むなら、引数の区切りを `（バイト値,1）` にする。そのままでは行のカンマで割れる。

| | |
|---|---|
| 追加される位置 | 末尾 |
| 同じ内容をもう一度追加 | されない。件数も増えない |
| 削除 | `（追加単語の削除,単語群名,単語）`。完全一致のみ |
| 辞書に書いた単語 | 削除できない。消せるのは追加した分だけ |
| 1行の書き換え | **できない**。削除して追加し直すと、その行は末尾へ移る。順序に意味があるなら、行の先頭に並べ替え用の値を持たせ、読む側で並べ替える |

1件も追加していないうちは、単語群が存在しない。呼ぶと `（所持品）` と出るので、`（単語群「所持品」の存在）` で確かめてから読む。

### 順に読む

**単語群は既定でランダムに選ばれる。**先頭から順に読むには、重複回避で順序を固定する。

```
＄単語群「所持品」の重複回避	無効、起動中
＄単語群「所持品」の重複回避	降順、起動中
：（for,1,（単語群「所持品」の数）,1,（call,1行表示,（所持品）））
```

- 「降順」が先頭から後ろへ、「昇順」が最後尾から前へ。**名前が直感と逆**
- 2行要る。すでに「降順」のときにもう一度「降順」を設定しても、読む位置は先頭に戻らない。一度「無効」にしてから設定し直す
- 途中で読むのをやめると、次はその続きから始まる
- `有効、起動中` にすると、全部引くまで同じものが出ない（山札など）。引き直すときも、別の方法を挟んで設定し直す

## 名前を組み立てて、処理を1つにする

```
＄リストの名前	アイテム一覧
（（リストの名前）の1ページ件数）    → （アイテム一覧の1ページ件数）として読まれる
```

内側が展開されてから、外側が名前として読み直される（→ `syntax.md`「評価モデル」）。
処理部は名前を組み立てて読むだけにし、一覧ごとの設定は `＠アイテム一覧の1ページ件数` `＠アイテム一覧の説明` のように定義を並べる。
別の一覧を足すときは、名前を変えて定義を並べるだけで、処理部に触らない。

組み立てた名前は、そのまま選択肢の ID や引数になる。**利用者が名前を決めるなら、使えない文字を書く前に伝える。**

| | |
|---|---|
| 引数の区切りになる文字 | `,` `、` `，` `､` は使えない（→ `syntax.md`「引数区切りの誤爆」） |
| 選択肢の ID にも使うなら | `On` で始める。でないと里々が ID を書き換える（→ `internals.md`「選択肢の ID 書き換え」） |
| `replace_after.txt` に書かれた文字列 | 名前の中にあると、出力の直前に置き換わる。置換の対象を読んで、使えない語として伝える（→ `internals.md`「置換ファイルのタイミング」） |

## 調整する値は、設定として先に置く

作者が後で変えたくなる値（速さ・間隔・回数・確率・件数・ボタンの文言など）は、処理に埋めず、`＠` で定義してファイルの先頭にまとめる。処理部は下に置く。

```
＠On_リストの表示項目数
6

＃半角カンマを使わない
＠On_リストの次へ
次へ
```

処理部からは `（On_リストの表示項目数）` のように読む。
利用者が書き換えるのは、名前の下の1行だけになる。括弧の中を編集させると、**カンマや括弧が欠けて黙って動かなくなる。**

| 決まり | 理由 |
|---|---|
| 名前は長く、役割が分かる形にする | 短い名前は既存の定義とぶつかる（→ `syntax.md`「変数・単語群・トークは名前空間を共有する」） |
| 機能の名前を頭に付ける | 既にある辞書に足しても、ぶつからない |
| 日本語で書く | 読むのはゴーストの作者なので、略語より通じる |
| 値は1行だけ書く | 複数行あると、そのうち1つがランダムに選ばれる |
| 同じ名前の変数を作らない | 名前空間を共有していて、片方が読めなくなる |
| 機能の名前を選択肢の ID にも使うなら、機能の名前を `On_` で始め（`On_リスト`）、設定の名前はその後ろに続ける（`On_リストの表示項目数`） | `On` で始まる ID だけは、里々が書き換えず、その名前のイベントが直接起きる（→ `syntax.md`「選択肢」）。ID に使わない機能なら `On_` は付けない |

### コメントには、何を書くと壊れるかだけを書く

名前が説明を兼ねるので、ほかは要らない。読むのはゴーストの作者で、プログラムを書く人とは限らない。専門用語を使わない。

- 文字列なら、入れると壊れる文字や長さ（「半角カンマを使わない」「1行に収まる長さにする」）。その値が処理のどこへ入るかから決まる
- 数値なら、動かなくなる境目。限界そのものではなく、余裕を見た値を書く（「30より小さくしない」）。限界を書くと、その手前で不具合が出る
- なぜその値なのかは書かない。内部の事情で、調整する側には関係がない
- 境目が分からないなら、性質だけを書く（「短くしすぎると動きが乱れる」）。SSP とのやりとりが絡む値はテスターで測れない（→ `testing.md`「確かめられないこと」）。**知らない値を推測で書かない**
